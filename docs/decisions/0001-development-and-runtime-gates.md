# ADR 0001：分开记录开发依赖与运行验收闸门

- 日期：2026-11-18。
- 状态：本轮实施采用。
- 背景：用户要求保存逐批 review guide，继续分阶段完成项目；当前没有补充 KVM 宿主的安排。

## 决定

原计划要求 P0 全部通过后才开始 P1。调整为：允许开发和验证不依赖待验基础设施的 P1 模块；执行不可信代码、构建用户项目、部署和运维变更，仍要求相关隔离、授权、原生集成及证据闸门通过。

本轮 P1-A 只实现受认证的资源登记、持久化任务接收/查询和排队取消。它不消费执行队列，不拉取仓库，不执行依赖安装/项目命令，不连接 Komodo 或 Whiskers，不对外承诺 P0 或完整 P1 已通过。

## 约束保持

蓝图 v6 的三条闭环、五种逻辑角色、双向 MCP、单维护者/单工作区/全局一个执行中工作流、人工确认、一次性虚拟机隔离与真实结果核对均保留。Docker 只用于可信 PostgreSQL 测试，不替代项目执行隔离。

不把测试身份服务当成部署好的 Keycloak，不把签名 JWT 夹具验证当成真实 SSO 集成，不把排队任务当成 Agent 已执行。所有 capability 默认关闭，后续在具有相关证据的交付中逐项接入。

## 交付方式

PR #1 保留 P0 起步代码及固定版本导读。P1-A 使用基于 PR #1 分支的独立草稿 PR，先提交计划，再逐需求实现及验证，最后保存对应 review guide。前置 PR 不因继续开发而自动合并。

这次调整的是开发顺序，不豁免待验功能，不宣称完整项目已完成。基础设施具备条件后补做真实隔离、发布、原生确认和恢复验证。
