# P4-D1 · 正式任务固定生效规则版本

接续 P4-C 的规则包发布与双语门户。这个批次让后续任务取得唯一可追溯的规则版本集合，并为实际扫描、运维复用与审批失效提供输入。 [前置 PR #145](https://github.com/MaLaNg116/itervane/pull/145) · [P4 总计划](p4-rule-learning.md) · [运行约束](../decisions/0001-development-and-runtime-gates.md)

1. 在正式开发和诊断任务入队事务中，按当前项目、工作区和任务用途读取已审核发布的最新激活记录。记录包、版本、正文摘要、审核摘要与激活序号。开发固定设计 Skill 和代码规则，诊断固定 Runbook。重复请求返回原任务及原依据，后续代次保留同一任务的历史版本集合。
2. PostgreSQL 保存不可变快照，事务校验项目、用途、有效激活记录及全部适用规则。使用工作区级事务锁为规则版本切换和快照分别排序，保证跨包读取一致。使用统一大小上限；超限时暂停接收该任务并保留可解释的错误。
3. 双语 HTTP 与只读 MCP 提供任务实际选中的版本及摘要，沿用项目权限。后续将同一快照并入审计、复验、人工发布和 Runbook 处置。历史任务保留原引用，迁移前任务明确显示没有记录。
4. 真库验证项目范围、工作区范围、用途过滤、并发切换、幂等、撤回和回滚。在后续批次用第二个实际项目验证已发布代码规则的命中与反例，再以独立的故障任务验证 Runbook、双重审批、次数上限和恢复证据。

从此快照到正式扫描、运维处置与授权更新的接入由 P4-D2 至 D4 验收。版本集合与工具执行权各自由已有的授权闸门核对。
