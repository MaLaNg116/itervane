# P3-C2b1 · 持久化处置准入与发布互斥

接续原生重启协议 #87。已获批的提案经过控制面的执行准入，在 PostgreSQL 建立单条处置记录。同一环境的发布和运维共同争用环境行锁。 [处置执行计划](p3-c-operations-execution.md) · [前置 PR](https://github.com/MaLaNg116/itervane/pull/87)

1. 处置通过提案 ID、指纹和决定版本关联已批准动作。准入重新读取当前授权、实际发布版本、已登记目标和数据库时钟。一个提案最多建立一条记录，重复准入只复用同一记录。
2. 发布入队与处置准入在同一环境行锁下核对互斥，验证两个方向的竞争。撤销决定与撤回尚未派发的处置原子提交。新申请清理已过期、仍处于预留的处置记录。
3. 用真实 PostgreSQL 验证并发、撤权、有效期、发布冲突和事务回滚。保留独立诊断记录及原人工审批历史。

C2b2 接入任务入队、执行槽和租约。C2c 接入原生确认、只读核对和恢复结算，C2d 验收指定版本恢复。
