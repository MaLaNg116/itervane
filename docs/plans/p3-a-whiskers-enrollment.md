# P3-A2-B1 · 登记只读运维后端

从已核验的发布证据取得容器 ID，由安装维护者独立登记该环境的 Whiskers 地址与服务器 ID。绑定引用当前正式发布登记的代次和指纹。Whiskers 独立登记使已经核验的发布保有原始回执。 [P3-A2 计划](p3-a-observation-evidence.md)

1. 复用标准服务地址和 Whiskers 服务器 ID 校验。严格登记文档包含环境、发布登记代次与指纹、Whiskers 地址和服务器 ID。数据库用完整环境关系限定一个登记，并保留自己的递增代次。
2. 维护者通过限定长度的配置文件登记。事务锁定受保护环境，在当前发布登记一致时生效。相同文档返回现有代次，换绑产生新代次。命令回执仅显示环境、代次与指纹。Read 密钥由后续 Worker 独立注入，本批的登记文档没有凭证字段。
3. 在已有项目授权及发布证据上读取登记，核对双方代次与指纹。发布登记变化后旧绑定失效。后续诊断任务固定该绑定并在读取和保存时重做校验。真实 PostgreSQL 验证幂等、并发、过期输入和两个项目间的绑定。

随后接续 A2-B 的诊断事务、队列、执行槽与原生结果回写。服务端授权继续约束下游凭证，运行时观察范围最终由已发布容器和最新登记共同确定。
