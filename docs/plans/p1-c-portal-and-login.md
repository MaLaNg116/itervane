## 2. 本批用户闭环

`打开门户 → 切换中英文 → 外部身份服务登录 → 当前领域授权 → 创建/选择项目 → 登记 HTTPS 仓库 → 提交固定 Git 版本 preflight → 查看任务/事件/原因 → 取消或带版本重试 → 注销/重新登录后重新查询`

任务由现有 TaskService 和 Worker 推进。缺少经过验证的 VM 时，门户清楚显示等待 Runner，不展示虚假扫描报告、批准或发布成功。

## 3. 技术选择与边界

- 门户：既定 React 19 + Vite + Ant Design 6，新增 `packages/portal`，不套企业规范。
- OIDC：复用 oidc-client-ts，Authorization Code + PKCE S256；Keycloak 为首个真实验证提供者。详细决定见 ADR 0003。
- API 继续只认 Bearer，不增加 Cookie 登录、密码接口、query token 或前端模拟身份。MCP resource audience 和 scope 不受门户配置影响。
- Token 只在内存；登录事务 state/verifier 暂存 sessionStorage，处理后清理；语言偏好可本地保存。刷新页面后通过明确的重新登录复用 IdP SSO，不把浏览器持久存储当作登录凭证。
- 浏览器请求使用同源 `/v1`，复用严格共享契约、现有 JWT 验证及数据库当前权限。新增只读 project access 契约支持按钮展示，服务端仍是授权边界。
- 数据查询/缓存复用 TanStack Query，按身份/语言/资源分键；退出或身份失效清理私人缓存，轮询有界，错误不显示旧缓存数据。
- API 同源提供受信任门户构建与最小公开配置；不公开环境变量、凭证或运行文件。CSP、回调专用路径和不记录查询参数保持约束。
- 不增加数据库业务迁移；不运行上传项目，不连接 Komodo/Whiskers，不以登录替代人类批准。

## 5. 测试与证据

保留 P1-B 的严格类型、47 单元/50 PG 测试等基线；新增与变更相称的契约、配置、当前权限、静态路径/响应头和浏览器行为验证。真实登录用独立、loopback-only 的可信 Keycloak 容器和随机测试凭证，不以伪 token 或 mock 登录作为端到端证明。

Playwright 运行真实构建、真实 HTTP/JWT/PG/Worker；不运行不可信项目代码。Docker 在此只承载可信基础组件，不替代 VM 隔离。镜像按官方版本和 digest 锁定，记录环境要求；第三方身份服务/TLS/反向代理仍需维护者按部署环境配置，不把本地开发模式说成生产验收。

所有诊断不记录 token、code/verifier、密码或 IdP 原始错误；不保存含登录凭证的浏览器 trace。guide 固定代码、阅读顺序、测试结果、剩余闸门及 PR 依赖。
