# P2-D3-B · 隔离重放与重新扫描

依赖 [P2-D3-A #24](https://github.com/MaLaNg116/itervane/pull/24) 锁定的正式复验输入。按 [P2-D3 计划](p2-d3-formal-verification.md) 证明已核验的候选能在新客体重建，并得到可与基线比较的扫描回执。下一批续接基线测试、构建及镜像证据。

## 重放与执行边界

- Worker 从当前 run 的持久输入和操作账本取材。请求绑定复验输入、仓库与提交、原始和目标清单、执行代次、合格镜像与受保护扫描输入。候选分支一并绑定已经核验的规范修复命令和补丁指纹。
- Runner 使用新的短生命周期客体重新验证固定 Git 来源。原始分支直接以校验后的清单扫描，修复分支从相同原始字节重放补丁并核对已记录候选的整个清单。文件模式、未修改目录及受保护路径也在核对范围内。只读扫描目标由受信任的客体边界发布。
- 在受限的取源身份下完成候选文件及 npm 投影的校验和发布，然后由既有扫描身份从只读挂载读取。扫描入口核对新增工作树与依赖投影的挂载标志，并重新验证整个候选摘要。原始 Git 树和重放后的候选清单分别记录，二者通过规范命令关联。
- 扫描器、策略与数据库的实测摘要等于复验 profile。旧审计与当前复验使用的扫描证据不可比时，按当前复验 profile 复扫原始快照，再与候选结果比较。已存审计继续保留供追踪。
- 运行、心跳、提交和回收都绑定当前执行权。先确认客体退出和资源清理，再允许新的隔离作业。租约失效或撤权后只保留回收所需事实，证据与产物继续由当前授权控制。

## 扫描比较

- 对比使用整个已归一化回执。每项扫描都要完成，且排查工具、保护策略和数据库指纹一致。扫描失败、部分覆盖或配置不一致报告明确状态。
- 归一化发现编号仍绑定其所属清单，仅用于引用证据。比较时按扫描器、路径和规则聚类；npm 再使用包名和实际安装的版本。Gitleaks 比较同规则同路径的命中数量，行号移动仍作为该组残留。比较报告保留前后证据编号和数量，供 Agent 解释新增、残留与退出的范围。
- 诊断使用受控标识和脱敏统计。回执记录复验输入、配对清单、扫描环境与检查结果。P2-D3 的完整复验结论还依赖基线、针对性测试与镜像，发布权由 P2-E 的审批闸门授予。

## 分项验收

| 交付 | 验收 |
| --- | --- |
| 重放协议与候选清单 | 原始和修复两条入口在相同资格约束下得到可核对清单；替换命令、改后字节或旧输入需要拒绝 |
| 受保护的配对扫描 | 使用固定的 dotenv 与 npm 维护者样例，分别核对原始发现、候选目标结果、未变内容和客体清理 |
| 对比结果 | 覆盖正常移除、只移动行、引入新发现、版本变更后仍存在公告、覆盖不足与数据库变化 |
| 真实验收与导读 | 使用托管 KVM 复现两类修复，保存固定源码、双份扫描摘要、清理、事务与恢复证据；初步状态可用中文和英文表述 |
