# P4-D3a · 运维诊断读取固定版本的 Runbook

运维任务已经在收件事务中固定已发布规则。本批让诊断 Agent 通过已有的发布证据读取这份 Runbook 指导。 [P4 计划](p4-rule-learning.md) · [#153](https://github.com/MaLaNg116/itervane/pull/153)

1. 复用正式任务的版本解析，按任务快照读取包版本、激活序号、人工审核和已通过的候选验证。核对 Runbook 的结构化样例结果。历史读回保留当时的版本。
2. 在现有租约下把有界重启指导附到发布证据。对两种已停止状态分别表示可用版本、无匹配或多条匹配。指导只包含已核对的版本、现行动作的前提和结果判据。保留原工具目录、预算、项目隔离和受控执行流程。
3. 校验新证据的任务快照摘要和回执引用。用真实 PostgreSQL 验证新诊断读取已发布版本、模型上下文得到等量证据、撤回后保留历史读回，以及无 Runbook 任务的既有轨迹。中英文描述继续由现有消息字典提供。

D3b 将唯一适用的已引证 Runbook 接入重启提议和双重审批，按实际目标、版本、执行次数和停止条件验证效果权限。D3c 在后续真实运维任务里复用它，核对独立观察的实例、启动时间和受保护健康响应。 [v6 蓝图](../blueprint-v6.md)
