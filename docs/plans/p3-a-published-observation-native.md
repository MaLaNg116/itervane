# P3-A2-B2-C · 观察本轮正式发布的容器

在一次独立托管 KVM 场景中沿用冻结源码、真实 Runner 复验、人工审批、Komodo 发布和受保护入口的正式路径。随后使用同一发布留下的应用、环境、容器与镜像证据创建诊断。 [执行批次](p3-a-observation-execution.md) · [正式发布验收](p2-e-protected-release-job.md)

1. 在本轮专用 Docker 主机运行固定版本 Whiskers。策略只允许容器详情读取。通过原生页面生成独立 Read 密钥，随已安装的 Worker 注入。登记与密钥分别记录和携带。
2. 执行正式诊断 Worker，验证任务读取的是 Komodo 实际部署的同一个容器。对照 PostgreSQL 绑定、实际回执、已核验的发布操作和派发记录。使用现有任务 HTTP 与外部 MCP 查询同一状态，对照双语事件。
3. 使用本轮统计的实际外部状态和数据库记录生成脱敏报告。独立核对发布操作数量和容器身份，确认观察完成后执行槽释放。本轮 Whiskers 随夹具清理。

原生场景验收成功后接续门户和 MCP 的诊断接收与回执读模型。发布期间继续使用 P2 已验证的脚本模型，真实模型运行证据单独保留。
