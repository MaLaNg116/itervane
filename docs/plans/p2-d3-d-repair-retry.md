# P2-D3-D-C2 · 复验失败后的受控返修

基于 [正式 Worker 复验 #35](https://github.com/MaLaNg116/itervane/pull/35)。把可信失败事实带入下一次修复决策，保留上一代次的差异、证据和结果。返修使用现有串行队列、当前项目授权和隔离 Runner。 [v6 蓝图](../blueprint-v6.md) · [独立复验计划](p2-d3-formal-verification.md)

| 批次 | 工作 | 验收依据 |
| --- | --- | --- |
| C2-A 返修记录与授权 | 从当前代次的正式复验结论及对应回执固定失败事实。记录任务、当前与后继 run、前一候选摘要、失败证据和返修预算。合并发布结论、创建代次、入队、写入事件与释放执行槽的事务。 | 重复决策只有一条后继记录，事件或入队失败时整体回滚。取消、撤权、旧租约和错配证据无法触发后继 run。 |
| C2-B Agent 与受控工具 | 在同一固定 Git 原稿上准备新候选，复用隔离扫描、结构化模板和受限代码修改。向修复角色提供上一轮失败项及操作引用，规则和 Runner 配置沿用被冻结的验证要求。 | 新角色根据已观察失败选择具体调整，替换补丁具备真实差异。同样的失败候选、无可信改动方向、缺证和预算耗尽进入人工处理。 |
| C2-C 完整返修验收 | 第二代次重新取得自己的审计、修复和独立复验回执。中英文事件显示失败、返修与下一次结果。 | 至少一条正向路径以真实故障和不同候选复验通过。回归仍在、无改进、撤权和 Worker 中断的负例有明确停止理由，前一代次历史可追溯。 |

MVP 给同一任务一次自动返修额度。仅有已经核验的失败以及现有工具能够定位的修改目标时分配额度。复验建议作为证据说明提供给修复角色，具体操作仍由 Runner 与平台授权核验。清理未知先等待核对。

旧代次的检查点只供历史查询。新代次拥有独立的租约、检查点、事实和结果，旧候选保留对应的源码和补丁。后续发布仍按 P2-E 核对当前代次证据、目标环境和人工批准。D-D 将同一证据链呈现在双语门户与 MCP 中。
