# P5-C2 · 从既有控制面升级参考安装

本批用真实 PostgreSQL 17、Keycloak 和参考安装命令演练升级。以前置指定版本恢复的交付分支为比较基线。 [P5 发布验收](../implementation-plan-v2-ts-postgresql.md#p5-验证可靠性并形成可复现的开源交付) · [前置 #170](https://github.com/MaLaNg116/itervane/pull/170)

1. 在新建的参考 Compose 项目中，通过固定历史基线 `50fe5b16b5c3ff23dc3cfc9fd5928e3fd42681d8` 的实际迁移、资源与入队服务创建旧工作区、项目、仓库和未运行任务。身份与当前生成的 Keycloak realm 对应，旧应用与升级器均使用各自的限定数据库角色。
2. 保持服务静止，执行当前的 `reference:init`，再重跑一次。核对旧迁移记录完整保留、新迁移应用一次、原工作区及任务没有重新生成，任务与持久队列的关联保持一致，运行角色仍没有 DDL 权限。
3. 启动当前版本，使用真实 Keycloak 和浏览器读取旧任务。让 Worker 从原队列消费并进入 Runner 闸门，核对外部 MCP 读回及幂等重放。托管验证固定前后源码，并保留脱敏迁移证据。
4. 提供双语升级步骤，说明应用前冷备、保持配置和身份卷、暂停执行、重复初始化、升后核对以及从升级前冷备恢复。P5 冷备批次继续提供数据库、产物、外部保护与恢复的实际演练。
