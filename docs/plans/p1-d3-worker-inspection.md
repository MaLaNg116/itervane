# P1-D3-C2 Worker 准入、回执与恢复

基于 `8bfc71d` 已合入的本机 Runner 控制器。沿用 `source.inspect` 工具、已登记 Git 来源、单全局执行槽位、固定检查计划和现有项目授权，把实际来源检查变成可追溯领域事实。 [D3-C 总计划](p1-d3-qualified-inspection.md) · [C1 导读](../reviews/p1-d3-qualified-controller.md)

| 顺序 | 工作 | 验收 |
| --- | --- | --- |
| 1 | 增加不可替换的检查尝试账本。绑定任务、项目、仓库、提交、计划、观察到的 Runner 输入摘要、Worker 与 fence。保留已确认回收、结果未知和已发布回执。 | PostgreSQL 拒绝重复尝试、绑定替换、迟到发布、越界证据及清理不完整的回执。存量任务与检查计划继续可读。 |
| 2 | Worker 在现有租约事务内准备检查，跑过本机 Runner 独立身份。用当前数据库许可授权每个心跳，结束后重校验再发布脱敏回执和事件。 | 真实 Worker 连接真实 KVM，执行中撤权和取消可停止；新 fence 拒绝旧回执。失败和未覆盖检查有明确状态。 |
| 3 | 查询和重领共用正式记录。已有尝试不确定时，经控制器核对工作区与回收状态后再决定是否创建新尝试。API、MCP 和双语门户展示相同证据与覆盖边界。 | Worker 重启、暂时断连、授权撤销、幂等、当前代次访问和 GSAP 行为通过回归，主线保留端到端证据。 |

验收在明确登记且已验证的测试环境执行。源码扫描完成后，任务可以进入后续审计环节。发布、普通命令执行与运维资格继续分别验收。
