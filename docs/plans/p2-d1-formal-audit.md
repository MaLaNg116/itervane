# P2-D1 · 正式源码证据与内置审计 Agent

以 P1-D3-C2 的固定源码检查、回执和执行权为前置条件，落实蓝图 v6 的 ReAct 审计以及 [TS + PostgreSQL 实施计划](../implementation-plan-v2-ts-postgresql.md) 中的 P2.1、P2.2。本批先完成正式审计，修复、独立复验和 Komodo 发布继续沿同一任务链推进。 [C2 导读](../reviews/p1-d3-worker-inspection.md) · [P2-A 样例](p2-a-agent-harness.md)

## 依赖和边界

- P1-D3-C2 提供经当前执行权正式发布的扫描回执。根据任务、固定提交、检查计划、快照清单及扫描器覆盖核验入口。没有可验证回执或回收仍未知时，沿用前置检查等待状态。
- P1-E 的规则目录提供指导。任务固定目录指纹和规则集合。Agent 把规则资料视为有来源的输入，服务器继续控制权限、检查标准、预算和工具范围。
- P2-A 提供已有 ReAct 节点、模型适配器、预算与停止条件。可信样例和正式执行需要各自可核验的来源。复用 Anthropic 和 OpenAI 协议适配器，首期正式验收使用一种明确获准的模型。
- P2-B/C 的候选、审批和发布账本保持原有资格闸门。审计阶段只访问当前任务的归一化扫描和允许的规则资料。源码片段工具在后续工作区接入时另行核验隔离、读取边界和出域许可。

## 计划与验收

| 顺序 | 交付 | 验收 |
| --- | --- | --- |
| D1.1 | 固定审计输入、规则和结果契约 | 输入绑定当前任务、run、原始检查回执、策略和规则版本。结果区分已确认、疑似和未覆盖，具备证据引用、影响和可执行的修复建议。 |
| D1.2 | 用当前执行权与正式检查点保存审计进度 | 保留前置图已有发布指针，为审计图建立受约束的发布指针。用真实 PostgreSQL 验证跨图读取、旧 fence、未发布写入和变更后的固定输入被拒绝。 |
| D1.3 | 接入正式 ReAct 审计工具与模型 | 至少两种实际扫描观察触发不同的工具路径并形成有证据的发现。预算、持续无进展、模型故障、取消和权限撤销得到可复现的处理。 |
| D1.4 | 同一事务记录审计清单并提供双语查询 | 服务端复核检查点、执行权和引用后发布审计清单。门户和外部 MCP 按当前授权读取相同的发现、覆盖和阶段状态。审计完成后等待后续修复阶段。 |
| D1.5 | 真实运行、评测和导读 | 托管 KVM 和正式 Worker 产生真实固定源码证据。CI 使用固定的模型观察序列复跑，正常与回归样例有独立预期。已配置的真实模型另验两条调查路径并记录计量、结果和失败边界。 |

后续 D2 接入受限修复，D3 接入干净环境复验，P2-E 串联有效人审和 Komodo 的正式发布与核对。Semgrep 和额外代码规则继续使用各自的验收范围。 [v6 安全边界](../blueprint-v6.md#15-安全隔离与恢复边界)

## 当前模型验收基线

2026-11-21 在本机以 Anthropic 兼容协议复跑 P2-A 的中英文维护者样例。两个样例均收到真实工具调用和计量，在审计过程中进入 `provider_error` 人工状态。一次单样例诊断记录了同一端点先返回 HTTP 200、随后返回 HTTP 503。把模型中断、已使用预算和已有证据持久化作为正式审计的验收项。两条完整的真实模型路径仍待通过。

正式审计的环回诊断复现了工具消息回放后的 HTTP 503。只发送已接纳的结构化观察后，模型读完两种扫描并正确引用证据，提交的说明数超过了实际发现数。D1.5 将正式模型请求改为基于持久化观察构建，只在两个扫描都返回后提供结论工具，并在工具参数中列出可引用的编号和准确的说明数量。服务端继续独立核对每个引用与发现，原有审计样例沿用其多轮协议验收。复跑需覆盖多余说明拒绝、零发现清单及中英文真实模型调用。
