# P5-B4 · 从干净参考安装完成受保护发布

本批从空环境开始，使用参考控制面与专用 KVM Runner，把一个登记的示例项目从外部 MCP 提交、审计、修复和独立复验推进到门户人工确认、Registry 导入和 Komodo 发布。运行结果由受保护入口和另一次容器观察核对。 [参考审计 #164](https://github.com/MaLaNg116/itervane/pull/164) · [现有发布 Worker 安装](../reviews/p2-e-release-installation.md)

1. 保留已验证的参考安装、真实 Keycloak 授权码与 PKCE。外部 MCP 显式取得写范围并提交同一固定版本。可信宿主加载冻结的扫描、构建和 OCI 输入，以及登记的 npm 升级清单。测试模型仅提供 Anthropic 协议响应，应用 Worker、依赖修复、VM 构建和扫描均使用正式入口。
2. 启动锁定的临时 Registry、Komodo 和应用保护入口。使用正常资源接口创建应用和环境，复用 register:release-target 登记当前环境、独立复验配置、健康和保护探测。发布进程只取得登记目标和下游专用凭证。
3. 由外部 MCP 请求发布候选，再以真实登录的维护者在门户确认。核对 MCP 身份无法使用门户批准，确认前无发布操作。经正式发布 Worker 执行后，读回同一审批、镜像、原生更新、应用版本和健康记录。核对保护入口的匿名拒绝、实际运行容器、全局执行槽释放与 Runner 回收。
4. 在三个各自从空环境启动的托管 KVM 作业中运行同一完整开发路径。每次保留独立的项目、任务、复验、人工审批、发布操作与运行核对回执。提供可自托管配置和双语操作说明。后续批次复用同一参考部署，接通运维与规则复用。
