# P4-C2c · 候选验证任务与可信证据账本

接续 [#142](https://github.com/MaLaNg116/itervane/pull/142)。候选从当前项目的不可变提炼回执进入单槽任务。验证结果依赖实际样例和执行证据，后续人工审核按该结果摘要绑定。 [P4-C 总计划](p4-candidate-validation.md)

1. API 绑定提炼候选、正文摘要、项目写权限、当前授权代次及安装配置。以已登记源码坐标注册验证角色任务，沿用事务内入队和幂等。配置未安装或不完整时拒绝新的样例执行。
2. 代码规则验证在准备后持久化请求、工作区、基准和命令摘要。Worker 按当前租约向 Runner 发送固定候选。接管时先独立核对已无活动域，未知清理转人工。Runbook 使用固定判据与正反样例，保留判据版本。
3. 结算在同一事务复核任务、候选、当前执行权、改动范围、结果和域清理。保存不可变证据及任务事件，通过、失败、不可用分别展示。API 查询按项目授权和语言投影。
4. 真库覆盖重复入队、校验失败、授权变化、模型候选替换、错误回执及租约过期。托管场景从实际健康修复得到代码候选，调用正式接口让其进入另一个 KVM 域。受控重启案例通过正式任务验证 Runbook 判据，后续 P4-D 再证明生产复用。
