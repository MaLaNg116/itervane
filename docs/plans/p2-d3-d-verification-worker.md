# P2-D3-D-C1 · Worker 接续正式复验

本批衔接 [复验角色 #34](https://github.com/MaLaNg116/itervane/pull/34)。一个任务的固定原稿或已发布的修复候选由正式 Worker 继续复验，保存可供后续返修、用户查询与候选冻结使用的结论。 [D 阶段计划](p2-d3-d-formal-verification-agent.md)

| 工作 | 验收依据 |
| --- | --- |
| 配置正式复验 | Worker 管理端提供固定 Runner 镜像、扫描输入、构建配置、受保护基线及 OCI 输入。自动复验同时要求有界模型、同一 Runner 镜像和归档保留。现有未配置的 Worker 保持审计及修复的暂停出口。 |
| 原子交接 | 原稿须有完整审计及无发现的原始扫描，修复件须有可信的已发布候选。审计或修复结果、相应事件、固定复验输入和阶段状态一起提交。Worker 承接同一执行租约，重领从已提交的阶段继续。 |
| 持久复验结论 | 当前租约绑定复验输入、已核验回执和结果检查点。一次事务记录有界证据、角色意见、状态和事件并释放执行槽。丢失的执行权、回执或绑定变化不能产生正式结果。 |
| 失败与缺证 | 基线回归、源码残留或新增发现进入需人工处理，并保留事实和意见。无回执时记录不可用或待核对，结果未知期间沿用既有隔离和核对约束。 |

覆盖正常队列的无发现原稿和已修复候选、503 基线、断连后执行权重领、撤权与配置漂移。数据库断言必须使用真实 PostgreSQL。中英文事件沿用统一契约。

D-C2 在实际失败证据上增加受控返修代次与预算。D-D 将有权限的双语结果接入门户及外部 MCP。P2-E 复核候选、环境、证据和人工批准，完成真实发布。
