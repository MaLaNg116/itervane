# P2-E · 当前候选的人工审批与真实发布

以 [正式复验 #35](https://github.com/MaLaNg116/itervane/pull/35)、[受控返修 #36](https://github.com/MaLaNg116/itervane/pull/36)、[复验查询 #37](https://github.com/MaLaNg116/itervane/pull/37) 与 [任务详情 #38](https://github.com/MaLaNg116/itervane/pull/38) 为基线。把当前代次的独立复验接到已登记目标的人工审批和真实 Komodo 发布。 [v6 蓝图](../blueprint-v6.md) · [实施计划 P2](../implementation-plan-v2-ts-postgresql.md#p2-跑通-agent-审计修复复验和发布)

## 依赖与交付顺序

| 批次 | 交付 | 验收 |
| --- | --- | --- |
| E-A 固定发布候选 | 由服务器重算当前正式复验、镜像、来源和目标绑定。候选包含固定 Git、源码清单、补丁、策略、结果及回执、OCI 归档与镜像摘要，以及当前目标、运行配置、验证和恢复方案。 | 从实际复验通过的候选产生可复核清单。第一代失败、旧代次、不完整检查、镜像策略阻断、归档指纹缺失、同任务范围外目标、配置变化均不能生成有效候选。 |
| E-B 人工决定与原子入队 | 用 P2-B 的身份约束、候选指纹和数据库时间承载个人模式的确认。门户显示变更、目标、期限与风险，中英文使用同一冻结记录。确认、操作账本和正式队列在同一事务中提交。 | 维护者身份、本人确认标记、重复决定、过期、撤权重授、取消及变更失效都用真实 PostgreSQL 验收。外部 MCP 提供经授权的进度和决策结果读取。 |
| E-C 制品导入与 Komodo 派发 | 审批后由服务端读取绑定 OCI 归档，在登记的镜像仓库核对实际 manifest digest。Worker 在有效执行权和环境锁下使用已登记的 Komodo 目标与最小权限凭证，写入正式操作并执行一次。 | 篡改归档、重打标、错误目标及撤权能阻止变更。真实 Komodo 记录与同摘要镜像对应，派发前后账本、尝试和回执均可追踪。 |
| E-D 实际运行核对与 P2 出口 | 独立检查运行镜像、配置、受保护访问和健康。对端响应丢失时按已记录操作查证实际运行；具备完整证据后结算任务。 | 从外部 MCP 发起任务，在固定公开或合成样例上完成至少两类缺陷的审计、修改、复验、人审与发布。回归、目标漂移和不确定结果有可复核证据。 |

E-A 和 E-B 沿用 [候选与决定](p2-b-release-candidate.md) 的状态语义。E-B 到 E-D 复用 [操作账本与环境占用](p2-c-release-reconciliation.md) 的事务判据；原样例保留自己的来源与证据标签。Komodo 协议和实测版本参考 [原生发布验证](../reviews/p0-komodo-native-delivery.md)。

## 绑定、执行和恢复

- 候选校验只读取当前任务的 formal SQL 记录和已经确认清理的 Runner 回执。Image 层必须有匹配的 Trivy 结果、冻结镜像策略、独立读取的归档摘要。P2-D 的读视图继续只提供有界的复验事实。候选资格由确定性策略计算。
- 决定绑定候选指纹、当前代次、授权版本、应用和环境配置以及有效期。获取环境执行权后重新读取数据库时间和最新绑定，保留最小权限的服务端调用身份。每次调用的目标和参数来源于登记记录。
- 一次发布操作具有固定标识。派发失败或响应丢失时先查询目标和运行证据。清楚确认尚未派发的步骤才可恢复执行。发现状态未知时保留待核对记录与相互冲突操作的环境占用。
- 参考环境使用临时 Komodo、登记的目标和镜像仓库承载公开或合成标准应用。在 KVM 客体中执行应用源码与构建，发布使用已验证的同摘要制品。验收记录包括实际运行版本、健康、访问保护和清理结果。

P2 的证据同时供 P3 的 Whiskers 诊断、批准处置和恢复验证使用。P3 另验收运维角色、MCP 工具边界与关联修复任务。
