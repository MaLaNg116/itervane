# P5-B5 · 从参考环境的健康事件恢复当前发布

本批在 P5-B4 的干净安装和真实发布之后继续运行。每次使用当次新建的数据库、实际实例、健康探测、诊断证据与原生审批。 [参考发布 #165](https://github.com/MaLaNg116/itervane/pull/165) · [运维安装](../control-plane-restart.md) · [P5 验收](../implementation-plan-v2-ts-postgresql.md#p5-验证可靠性并形成可复现的开源交付)

1. 用现有平台登记命令安装一个受保护环境的 Whiskers 观察目标和受限重启。健康探测、诊断与处置分别使用已登记的读取、写入和探测身份。重启 API 时保留真实 Keycloak realm、门户会话与外部 MCP 授权。
2. 先确认真实探测健康，再让当次试验的登记实例停止。生产健康 Worker 录入事件并事务排队，正式诊断经 Whiskers 读取该实例，给出处置建议。核对事件、任务、当前容器、发布记录和去重。
3. 登录者在门户生成提案、确认和排队。真实 Whiskers Operator 独立批准暂停的重启；门户之后继续执行。必须核对任一审批缺失时的停留状态、恢复前后的独立容器状态、保护健康、原生审计和持久回执。
4. 在三个独立参考环境保留上述证据，并核对各实例、审批、任务与恢复操作相互独立。使用脚本化 Anthropic 响应驱动正式 Agent 循环，说明各角色和下游的实测范围。指定版本恢复已有 P3 原生证据，参考环境回归、经验沉淀与完整发布审计在后续批次核对。
