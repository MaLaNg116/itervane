# P3-B3 · 正式任务的诊断证据与持久化

接续 [运维调查循环 #75](https://github.com/MaLaNg116/itervane/pull/75)。正式任务对同一已发布版本收集证据，沿用安装范围、项目权限、共享执行槽和数据库租约。 [P3-B 总体计划](p3-b-operations-agent.md) · [蓝图](../blueprint-v6.md)

| 批次 | 实现与验收 |
| --- | --- |
| B3a 发布证据 | 对照冻结请求、当前登记和已发布版本，读取同一应用环境最近两次已核验发布。核对当前绑定版本与两次发布的候选、派发和上线证明，前一版本须符合当前目标登记。有发布待核对或授权代次变化时拒绝。PostgreSQL 验证多次真实领域结算、跨项目、换绑和旧请求。 |
| B3b 冻结任务与证据预留 | 通过安装配置启用完整诊断。冻结模型、目标和读入预算，按 run 与操作 ID 原子预留，保存归一化事实。重试、停止、重领和已完成结果重放走同一事务与执行权边界。原有只读观察任务按已记录模式运行。 |
| B3c Worker 调查与结算 | 在每个工具、模型决策和发布检查点的边界复核租约及授权。使用实际 Whiskers 与发布证据，验证操作编号、预算和回执。按同一租约原子保存最终结论、事件和容器回执。 |
| B3d 读侧与原生回归 | HTTP、MCP 和门户共享双语结论和可追溯证据，覆盖当前授权与撤权。通过托管发布容器、实际 Whiskers 与数据库跑通同一任务，分别记录脚本模型的可复现验收与实模结果。 |

P3-C 使用核验过的建议接续本人审批、重启或版本恢复，以及独立健康验证。
