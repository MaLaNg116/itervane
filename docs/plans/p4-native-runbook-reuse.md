# P4-D3c · 托管环境真实复用 Runbook

延续受保护应用的原生重启验收，用一次已核验恢复形成可复用版本，再由后续独立任务引用该版本完成受控重启。 [P4 计划](p4-rule-learning.md) · [#155](https://github.com/MaLaNg116/itervane/pull/155)

1. 使用现有受保护目标、真实 Whiskers、Komodo 只读身份与独立 PostgreSQL。首次受控重启产生核验回执，并走提炼 Agent、样例验证、人工审核与发布。
2. 在同一已发布镜像上再次独立制造停机观测，创建新诊断任务。通过 HTTP 和外部 MCP 对齐任务规则快照、已发布版本、被引用的诊断证据和呈批版本。门户与 Whiskers 分别人工确认后，核对只有一次实际重启，以独立浏览器审计、容器启动时间和受保护健康验证结案。
3. 在该 Runbook 下复跑写入后回执中断。核对没有重复发送，后续只读核对保留未知结果和环境占用。在托管证据中绑定三次任务、审批、规则版本、调用、镜像和容器变化，注明模型使用脚本适配器。
