# P3-A · 已发布应用的运维观察

以 [实施计划 P3](../implementation-plan-v2-ts-postgresql.md#p3-完成真实-agent-运维和关联修复) 和 [Whiskers 原生验证](../reviews/p0-whiskers-native-approval.md) 为基线。先建立可授权、可追溯的只读观察，再接运维 Agent、原生确认和受控恢复。生产运维验收使用 P2 已核验的部署与入口证据。

| 批次 | 实现与验收 |
| --- | --- |
| P3-A1 原生观察 | 复用 MCP 客户端和 Whiskers 0.15.0 固定样例，按维护者配置绑定实例、预先登记的服务和单个精确容器标识。使用专用只读服务凭证，仅调用 `get_container_details`。从有界返回提取明确的容器标识、运行状态和观察时间。用真实 Whiskers 核对正常、停止、目标不匹配与超时。 |
| P3-A2 项目与发布证据 | 运维目标由项目授权、应用环境、下游登记和已保留的 P2 发布证据共同确定。在启动与消费时核对当前作用域，给观察保存任务、运行、目标版本和原生引用。真实 PostgreSQL 验证撤权、目标变更与发布占用。门户、HTTP 和外部 MCP 提供中英文结果。 |
| P3-A3 诊断接续 | 运维 Agent 使用已经发布的受限事实及健康读回，在预算内形成诊断、证据与下一步建议。人工批准、Whiskers 原生确认、重启和 Komodo 恢复另在 P3.3 验收。 |

第一个原生适配面以固定的容器标识获得最小观察。连接地址、凭证和允许服务均来自已登记的安装配置。返回值需要通过有界解析和目标匹配，保留状态、证据时间、机器原因及可关联记录。环境和授权状态在后续领域接入时使用现有执行权和任务读模型。

完整 P3 继续覆盖停止恢复、指定版本恢复、审批过期、目标变化、人工期间环境占用、冷却、故障去重、关联修复与两种入口。
