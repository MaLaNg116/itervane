# P3-C2c3c · 重启 Worker 安装与原生闭环

#97 的托管标准应用已验证同一容器启动时间推进、匿名请求 401 和授权健康 200。#99 将独立证明和环境占用结算放在同一事务。本阶段接通安装、人工入口和真实后端。 [标准应用实证](https://github.com/MaLaNg116/itervane/actions/runs/45004903433/job/137154261966) · [结算计划](p3-c-restart-settlement.md)

| 批次 | 工作 | 验收 |
| --- | --- | --- |
| C2c3c1 专用 Worker | 明确启动入口，固定环境、准入登记、发布映射和 Whiskers 写安装。独立 Komodo 身份只读已登记目标，使用单独的 Keycloak 健康身份。队列消费按重启和只读核对分派。 | 配置错误在启动时失败。确认实际 Komodo 身份的读及 Inspect 权限，写和无关目标被拒。PostgreSQL 验证领取、两次人工边界间的暂停和最终核对分派。 |
| C2c3c2 平台人工入口与查询 | 在批准后的门户显式排队和续发，平台人工身份与原确认绑定。以授权检查投影双语处置回执；MCP 可读取结果。过期、撤销及手工核对有明确状态。 | 覆盖错项目、重复、撤权、过期、回执泄露及中英文交互。 |
| C2c3c3 同一应用原生验收 | 在已发布的标准应用上演练真实故障，完成平台批准、原生 Whiskers Operator 审批、同参一次续发及独立健康结算。 | KVM 报告关联原发布、冻结容器、原生审批、结算结果与执行槽，并覆盖中断后的只读接管。 |

安装配置仅交给专用进程。Komodo 读身份使用 `Read` 与目标专属 `Inspect`，启动检查原生凭证归属。Whiskers 写资格继续使用固定文件与登记证明，发送前重新核对。首期队列只消费重启动作，指定版本恢复按 C2d 接续。门户提交由完成原生验收的安装开放。
