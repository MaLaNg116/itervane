# P2-C 发布事务与运行结果核对

以已合入 P2-B 的 `main`（`d28a481f7c567dcd52c52ef7b1622ab25bee10ef`）为基线。实现 P2.4 的原子确认与入队，并演练 P2.5 的一次操作、结果未知及版本与健康核对。依据 [蓝图 v6](../blueprint-v6.md) §10、§11、§14 及 [TS + PostgreSQL 实施计划](../implementation-plan-v2-ts-postgresql.md)。交付到独立草稿 PR。

## 依赖与范围

P2-B 提供不可变候选、工作区所有者决定、候选指纹、授权实例及有效期。P1 提供 Drizzle 事务适配和 pg-boss。P2-C 将已有的人用确认写入、唯一逻辑操作和专用演练唤醒放入一个 PostgreSQL 事务。现有控制面、门户、MCP 和 Worker 继续执行 P1-E 路径。演练使用合成任务和可信材料，所有记录的正式发布资格为 `false`。

正式发布仍需 D2/D3 合格 Runner、真实复验及镜像扫描、经核验的 Komodo 目标映射、现有领域执行权与实际运行证据。本批的队列由测试驱动读取，同正式 Worker 使用的业务队列分离。发布适配器调用、真实 Komodo 验收及 P3 运维协调继续遵循 [运行闸门](../decisions/0001-development-and-runtime-gates.md) 和 [领域发布](../decisions/0002-checkpoint-publication.md)。

## 事务与恢复规则

| 过程 | 判据 |
| --- | --- |
| 人工确认 | 只有成功提交的样例确认生成操作；一个候选一个操作 ID。同 ID 作为队列 job ID，同一事务写确认、操作和唤醒。拒绝或重放不会新增操作，旧确认的重放不能补造操作。 |
| 领取 | 按候选及环境锁定范围，复核当前任务、证据、所有者授权和有效期。环境锁等待完成后重新读取 PostgreSQL 时间。队列只唤醒，账本状态决定能否预留。 |
| 竞争 | 同一个环境只允许一个处于已预留或待核对的操作。其他操作可等待。确认已失效的待处理操作停止，已经预留的操作进入核对流程。 |
| 核对 | 领取成功只表示已预留。响应丢失或证据不完整时保留环境占用，后续只查询实际结果。可信样例观察须匹配操作、指纹、目标映射、镜像和配置，并证明健康与访问保护。核对完成才释放占用。 |

测试以不同的 PostgreSQL 连接模拟恢复。没有可证明的对端结果时，旧操作会保持待核对状态以防重复执行。正式接入后应由现有 Worker 承担执行权、唤醒恢复和队列结算。

## 分项实施与验收

| 提交 | 内容 | 验收 |
| --- | --- | --- |
| C0 | 本计划 | 指定正式路径的资格与演练边界 |
| C1 | 操作契约、账本和专用唤醒 | 范围外操作、伪造资格和同环境并发占用受约束；迁移适用旧候选记录 |
| C2 | 原子确认、预留与核对 | 幂等、实时授权、结果未知、保护访问与版本证据、中英文状态 |
| C3 | PostgreSQL 演练和导读 | 同事务回滚、竞争、撤权、过期、重启后只核对、错误观察与正确观察、原入口回归 |

完整 P2 的验收仍包括真实部署、部署后保护访问和健康检查、实际运行版本匹配与副作用失联后的下游核对。
