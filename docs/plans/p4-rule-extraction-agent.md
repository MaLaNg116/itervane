# P4-B2a · 规则提炼 Agent 与候选合同

接续 [#137](https://github.com/MaLaNg116/itervane/pull/137) 的正式案例。规则提炼是 Itervane 第五种逻辑角色，复用 LangGraph 的 ReAct 调用、预算、检查点和权限门，在专用工具目录内形成待验候选。 [P4 总计划](p4-rule-learning.md)

1. 规则候选采用 JavaScript 或 TypeScript 的声明式 Semgrep 结构和三类样例。Runbook 采用受控重启的固定动作类型、允许症状、尝试次数、双重确认、目标绑定、恢复判据及停止条件。提炼输出携带双语名称、适用范围与风险说明。
2. 模型必须通过工具读取选定案例和同类历史索引。结论引用两份证据，并由运行时核对案例类别、重复项和候选类型。缺少证据或适用范围窄时保留案例，重复结论须绑定已知候选。
3. 固定候选语义摘要用于查重，包键、双语文案及样例不会掩盖已有的同类检查语义。模型只提交结构化候选，不具备发布、执行、构建或运维变更能力。
4. 正反轨迹覆盖强制读取、伪造引用、重复、非法动作、无进展、撤权、检查点接管和候选类型。模型协议验证使用可信夹具。B2b 在 PostgreSQL 与现有单槽 Worker 接入案例任务、固定历史快照及候选持久化，再对两条原生实际案例运行提炼。

候选与训练样例都需要后续受控验证。代码规则在 P4-C 使用固定 Semgrep CE 版本和一次性 VM。Runbook 继续调用既有领域审批、确认和独立恢复入口。
