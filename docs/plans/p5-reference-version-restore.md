# P5-B8 · 干净参考安装的指定版本恢复

本批沿用干净参考安装、真实 Keycloak、外部 MCP、合格 KVM Runner 和受保护发布入口，核对指定版本恢复的正向路径。以前置代码规则联验为比较基线。 [P5 发布验收](../implementation-plan-v2-ts-postgresql.md#p5-验证可靠性并形成可复现的开源交付) · [既有指定版本恢复](../reviews/p3-c-native-version-restore.md) · [前置 #169](https://github.com/MaLaNg116/itervane/pull/169)

1. 通过正式任务和受保护发布链路，将两个固定源码版本分别复验、批准并发布至同一环境。核对登记、部署和保护入口一致，两次发布的源码、镜像、运行版本及容器不同。
2. 停止该场景自管的合成应用容器。外部 MCP 通过真实 Keycloak 启动只读诊断和生成提案，提案须绑定现行发布与上一条已核验发布。使用固定的 Anthropic 协议响应，Whiskers 提供实际观察。
3. 核实批准前申请被拒且未入队，MCP 凭证无法提交已批准的恢复。真实门户维护者核对指纹和目标，确认并提交一次。正式 Restore Worker 使用目标范围内的 Komodo 写身份，由独立读身份核对更新、实际容器、受保护健康和匿名拒绝。
4. 对照双语门户、MCP、数据库账本和实际容器，确认历史镜像、恢复结果、发送及读回栅栏、环境持有权和全局执行槽。托管 KVM 保留绑定代码树的摘要。故障中断和撤销继续由既有原生用例覆盖。
