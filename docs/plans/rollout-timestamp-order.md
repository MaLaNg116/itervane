# 正式上线回执的时间顺序

P3-C2b2b 真库回归中，已完成的正式上线核验因数据库时钟回退被 `formal_rollout_outcome` 拒绝。记录中的完成时间比领取时间早约 0.8 秒。

用后续迁移修正正式上线核验的结算函数。完成时间取领取时间与结算时钟中较晚的值，继续校验当前租约、发布绑定、原生更新及健康证据。

在 PostgreSQL 17.12 中构造领取时间领先于当前数据库时钟的尝试，核对回执能够写入且完成时间落在租约内。复跑正常、错误证据和过期执行者场景。 [发现记录](../reviews/p3-c-operations-execution-intent.md)

复验 #83 时，同类回拨也触发了领取闸门。领取起点及请求期限统一使用同一条 SQL 的时间，数据库另读当前时钟检查租约尚未过期。保留运行中的旧 Worker 使用绝对期限的兼容路径，并复验 45 秒上限和当前执行者校验。
