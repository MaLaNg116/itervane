# P3-C2c3c2 · 重启人工入口与处置回执

在已登记的专用重启 Worker 上接通门户提交、原生审批后的续发和回执查询。沿用 v6 的双层审批，平台决定人与原生 Operator 分别在各自界面操作。 [安装与原生闭环计划](p3-c-installed-restart-worker.md)

| 批次 | 开发项 | 验收 |
|---|---|---|
| C2c3c2a | 门户 HTTP 排队与续发，双语 HTTP/MCP 只读回执。API 使用安装方注入的固定写侧登记证明。 | PostgreSQL 验证仅原确认者及同一授权可提交，重复只有一项调度，旧版本与目标变化拒绝。其他项目与撤权用户读不到回执。外部 MCP 仅有查询工具。 |
| C2c3c2b | 门户显示排队、原生批准编号和续发动作。隔离校验过期等待的只读接管与环境占用。 | 中英文浏览器验证暂停、失效与回执刷新。等待过期后进入独立核对，未结清的原生批准持续占用环境。 |
| C2c3c3 | 在标准应用真实发布后执行两层人工审批和实际恢复验证，接通安装入口。 | 托管 KVM 核对同一应用的发布、人工与原生批准、一次实际重启、独立恢复和执行槽释放。 |

首次排队引用冻结的提案指纹及批准版本。续发引用平台处置任务的版本、原始原生批准编号及调用指纹，并沿用原幂等键。回执提供任务、发布与原生批准的关联和脱敏核对结果。安装方控制可写入口的注册，标准 API 启动仍依赖 C2c3c3 的安装接线。
