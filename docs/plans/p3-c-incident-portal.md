# P3-C3-D3a · 门户事件、停止诊断与关联修复

接续 [#132](https://github.com/MaLaNg116/itervane/pull/132)。在应用的已发布版本和任务详情提供可追踪的双语事件、人工停止和修复确认。沿用 shadcn/ui、GSAP 披露动效及减少动效偏好。 [事件总计划](p3-c-operations-incidents.md) · [关联修复入口](p3-c-linked-repair-interfaces.md)

| 交付 | 验收 |
| --- | --- |
| 当前已核验发布显示健康状态及事件历史。诊断和关联修复任务显示同一事件及前后任务引用。 | 授权范围与下游读面一致。中英文、当前发布和历史发布的任务均能正确显示自身证据。 |
| 服务器按安装范围、门户身份、开放事件及停止状态投影人工停止入口。对话框绑定事件、当前发布或恢复执行。 | 确认前无需写操作。并发重复确认、授权变化和目标变化由原停止事务复核，界面更新原事件的处理凭证。 |
| 可写身份从已核验诊断准备提案。门户所有者确认原指纹，已应用补丁的发布填写固化后的提交。 | 只读用户可检索，门户确认和正常交付审批维持各自的授权。陈旧、过期、重复与已关联状态可见。后续任务通过原任务页查看隔离与复验证据。 |

在真实 PostgreSQL 上验证门户停止入口的权限和读取协议。用 Chrome 覆盖中英文、键盘确认、失效状态与关联导航；交互测试采用签名身份和稳定的响应夹具。组合验收由 D3b 在既有托管 KVM 发布场景中连接 HTTP、外部 MCP、停止与重新发布。 [原生发布场景](p3-c-linked-health-repair.md)
