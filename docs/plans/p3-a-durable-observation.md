# P3-A2-B2 · 可恢复的只读诊断任务

以正式发布证据及 Whiskers 登记为输入，沿用项目授权、PostgreSQL、执行槽和业务队列。工作流先保存可追溯的运行事实，再在 A3 将观察用于诊断。 [运维目标](p3-a-observation-evidence.md) · [后端登记](p3-a-whiskers-enrollment.md)

| 批次 | 工作与验收 |
| --- | --- |
| B2-A 诊断请求 | 沿用任务、run 与唤醒事务。诊断请求从发布绑定取得仓库、提交及数据级别，固定环境、发布操作、登记版本、镜像、容器和当前授权代次。真实 PostgreSQL 验证同键重放、跨类型冲突、权限与事务回滚。 |
| B2-B 正式执行 | 以 `operations` 角色路由到内部只读适配器，持现有可续租执行权。每次下游读取前及回写前，重新核对授权和两份绑定。Worker 按安装范围加载独立 Read 密钥。真实 PostgreSQL 验证取消、后继执行者、登记变化、发布占用及限次读回。 |
| B2-C 原生接续 | 使用 P2 已验收上线的同一容器和真实 Whiskers，核对观察结果、操作与公开读模型的来源一致。报告保存容器状态、观察时间、任务、run、执行代次和绑定摘要。 |

诊断输入和回执分别保存。队列仅携带任务及 run 标识。读取适配器返回的事实要在同一事务与任务结论、审计事件一起落库。下游通信在短事务之外执行。观察未完成或已失去授权时，保存有界机器原因，前端按现有词典提供中英文。门户与外部 MCP 接入仍按 A2-C 分批验收。

正式发布与运维共用业务执行槽。处于核对中的发布继续保留环境占用。未来的重启、恢复与对应审批由 P3 后续流程引入。
