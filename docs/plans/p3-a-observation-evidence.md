# P3-A2 · 将运维观察绑定到已发布版本

接续 Whiskers 原生观察。运维来源由已有项目授权、受保护环境、维护者登记及 P2 最后一次核验的发布共同决定。用户和模型输入只标识已登记的项目及环境。 [P3-A 计划](p3-a-whiskers-observation.md) · [P2 同一任务发布验收](../reviews/p2-e-protected-release-job.md)

| 批次 | 实现 | 验收 |
| --- | --- | --- |
| A2-A 已发布目标 | 持当前项目授权读取环境、正式登记、已核验发布及其原生回执。冻结部署、容器、镜像、分发更新和映射指纹。 | 真实 PostgreSQL 验证正常读出、跨项目、只读角色、映射换代与尚待核对的发布。最新证据损坏时阻断。 |
| A2-B 运维任务 | 独立登记 Whiskers 地址与服务器，服务端私下保管 Read 密钥。授权后事务入队，复用执行槽及代次。Worker 读取前和写入观察时核对当前授权、部署版本和发布占用。 | 真库核对重复请求、取消、撤权、后继 Worker 和发布并发。原生测试使用 P2 发布的同一个容器及真实 Whiskers。 |
| A2-C 业务入口 | 门户与 MCP 发起诊断并查询同一条持久化状态事实。中英文展示观察时间、状态和可处理原因。 | 真库与浏览器验证一致性、脱敏、跨项目拒绝、Auth/CSP 和现有动效路径。 |

选择最近一次 `verified_formal` 的运行证据，再核对发布候选、Komodo 更新、容器 ID、镜像和环境登记。登记的版本及指纹都要一致。发布处于排队、派发或核对中时，保持环境的发布占用语义。历史元数据只作为待验证的目标绑定，运行状态由 Whiskers 原生读回。

诊断任务拥有受保护的记录和明确的失败状态。观察授权及目标在请求接受、Worker 发起观察和记录结果时复核。继续沿用只读观察适配器，保留后续诊断、日志、指标及获批恢复的能力边界。 [v6 运维闭环](../blueprint-v6.md#12-运维-agent-具备真实但有限的执行能力)
