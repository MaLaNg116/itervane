# P4-D3b · 将已引证的 Runbook 绑定到受控重启

正常重启仍使用现有 Itervane 门户和 Whiskers 双重确认。匹配 Runbook 时，把审计证据中的版本、停机状态、次数限制和恢复判据纳入呈批及执行。 [P4 全阶段](p4-rule-learning.md) · [#154](https://github.com/MaLaNg116/itervane/pull/154)

1. 重启提议从诊断引用的发布证据选取唯一适用的 Runbook。在数据库中绑定规则快照、版本和被引用的诊断证据。遇到歧义时等待人工核对，原无匹配的重启流程继续使用既有审批。
2. 从呈批到执行发送，重新核对当前版本、项目授权、目标发布及独立观测的已停止实例。撤回或版本变化则重新诊断和授权。次数按可能产生重启效果的发送计数，Whiskers 明确仍待审批的回执可以在原上限内安全等待。未知发送结果进入现有只读核对，不重复写入。
3. 根据实际 Whiskers 回执、同一实例、新启动时间及受保护健康状态核对结果。出现明确健康失败时留存环境占用并转人工。保留历史证据和中英文审批界面。用真实 PostgreSQL 覆盖已引证重启、缺少引用、目标冲突、撤回和终止条件。
