# P3-C2c3c3 · 同一已发布应用的原生重启验收

以托管 KVM 上已完成正式发布的标准应用为对象，使用同一容器、镜像和受保护入口。接续 [双语重启门户](p3-c-restart-operator.md)。

| 批次 | 内容 | 证据 |
|---|---|---|
| C2c3c3a | 停止已绑定的合成应用，从真实观察发起诊断，记录平台人工批准、原生 Operator 批准和单次重启，随后由专用 Worker 独立核对。 | 一次实际原生审计记录、同一容器启动时间推进、匿名 401 和授权健康 200、环境占用与槽位释放。 |
| C2c3c3b | 补充实际批准撤销、结果未知及 Worker 重启后的只读接管。 | 旧执行权失效，原生许可未结清时保持环境互斥，核对流程不复发写动作。 |
| C2c3c3c | 接通自托管参考安装，验证装机证明、范围、权限和资格。 | 标准入口按受信配置注册，查阅安装与恢复说明可以重复验收。 |

原生验收用宿主拥有的已发布应用。Runner 继续在一次性 VM 中执行项目。Whiskers 使用摘要绑定的安装材料、单工具写凭证和独立的 Operator 登录，Komodo 核对使用另一受限账号。模型和控制面签发者使用可重复夹具，Whiskers、Komodo、受保护入口和底层运行证据使用实际服务。正式写入口在实际链路验收后由安装方接通。

## C2c3c3b 中断与接管验收

在正常重启完成后，对同一发布再触发一次故障。一次性 PostgreSQL 测试库通过行级触发器暂停本次原生成功应答的提交。确认 Worker 已进入该提交点后结束原进程并解除暂停，再通过平台人工入口撤销批准。保留实际 Whiskers 应用动作和原发送意图。

重启专用 Worker 后核对旧执行权过期、新执行权和独立运行证据。真实应用恢复健康，回执仍标记原生结果待核对，发布互斥持续生效。使用原生审计记录和续发账本验证接管未增加写入。测试钩子和进程控制只存在于托管验收。
