# P3-C · 运维处置的提案与授权

接续 [正式诊断 #82](https://github.com/MaLaNg116/itervane/pull/82)，实现 v6 P3.3 至 P3.5。处置读取已经核验的诊断，沿用单工作区、同一发布环境和全局执行槽。 [蓝图](../blueprint-v6.md) · [实施计划](../implementation-plan-v2-ts-postgresql.md)

| 批次 | 工作与验收 |
| --- | --- |
| C1a 处置提案 | 根据诊断证据冻结单次重启或指定已发布版本恢复。绑定诊断、当前发布、目标登记、提交者授权和有效期。真库验证同一诊断只产生一个提案、历史记录失效、串行冲突和无法从调查建议升级权限。 |
| C1b 人工审批 | 复用工作区所有者的门户身份边界和批准版本。确认、拒绝、撤销按提案指纹和当前授权留痕，个人模式记录本人确认。 |
| C2 处置执行与恢复 | 将已批准动作接入共享执行槽和同一环境互斥，关联下游确认与操作回执。Whiskers 重启，Komodo 恢复指定版本。控制响应丢失、重新领取、独立健康检查和结果未知。 |
| C3 触发与关联修复 | 健康异常可按去重、冷却和预算触发诊断。持续故障转人工，代码问题进入关联审计与修复。 [分批计划](p3-c-operations-incidents.md) |

C1a 通过可信内部领域服务保存提案，采用已登记发布策略的审批时长并校验诊断证据年龄。C1b 接入双语 HTTP、MCP 查询和门户审批。原生处置执行与恢复验证由 C2 验收。
