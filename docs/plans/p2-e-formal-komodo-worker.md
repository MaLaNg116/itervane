# P2-E-C4-B2 · 正式 Komodo Worker 和中断接续

接续 [Komodo 步骤账本 #51](https://github.com/MaLaNg116/itervane/pull/51) 及 [C4-B 实施计划](p2-e-formal-komodo-ledger.md)。在测试环境接通正式 Worker，发布入口的放行仍以 E-D 端到端验收为准。

| 状态 | 下一次允许的动作 |
| --- | --- |
| Registry 本轮已核验 | 同一操作保留环境占用，持久化交接给新的 Komodo 写入租约。新租约重新核对批准有效期、候选、目标和已核验制品。 |
| 配置意图已提交 | 当前租约在原生写请求前核对写权。中断后仅允许按意图回读配置，匹配获批镜像及运行配置方可确认。 |
| 配置已确认 | 派发前仍须有当前的批准及环境执行权。恢复需要重新取得可写租约，复用已确认配置。 |
| 派发意图已提交 | 当前租约发送一次原生 Deploy。成功往返时先记原生更新 ID，终态由独立读取确认。 |
| 派发待核对 | 有更新 ID 时核对原生动作、目标和身份。缺少可靠关联时停在人工核对，环境继续保留占用。 |
| 已记录原生终态 | 进入待运行核验，释放全局执行槽并保留环境占用。E-D 验证实际版本、健康及访问保护。 |

单独授权发送变更与读取结果。撤权、到期和取消会关闭写入，已记录的请求继续由原租约或受限的新观察租约核对。每个步骤最多三次自动重查，认领时记账，进程再中断也计入。

新增真实 PostgreSQL 并发和故障测试，以及使用临时 Registry、Komodo Core/Periphery 和真实批准制品的托管验证。分别演练配置写入后失去响应、部署已登记更新 ID 后终止进程，以及丢失原生更新 ID 时保留环境。每个用例核对写入次数、占用、连续 fence、双语事件和下游实际证据。
