# P2-E-C3-C2 · Registry 导入 Worker 与待核对恢复

基于 C3-C1 的归档凭据、唯一导入意图和 Registry 只读核对。 [PR #48](https://github.com/MaLaNg116/itervane/pull/48) · [发布步骤计划](p2-e-formal-release-registry-steps.md)

## 认领与中断后的状态

- 未准备导入前终止时，用现有正式队列重排同一操作。新 fence 重新验证归档，旧进程的暂存不参与恢复。
- 有导入意图后终止时，操作转为待核对并保留目标环境占用。等待和认领都使用原操作 ID，本次唤醒、队列尝试和 fence 各自更新。回队、任务事件与执行槽让渡同事务完成。
- 恢复者核对原意图、登记目标、候选指纹和当前执行权。恢复权仅用于查询 Registry。即使人已申请取消或原审批已过期，仍保存已发出操作的可核对事实。新的外部写入需要当前的完整权限。
- 查询实际镜像和配置。证据匹配后保留原导入 fence 和新观察 fence，交给 C4 或按已有取消完成结算。网络错误、结果缺失或错配继续保留待核对与环境占用。自动核对限制为三轮，下一轮使用延迟队列，超过上限时保留审计记录供人工核对。

## Worker 接线

1. 领取正式唤醒后通过 Runner 读取获批 OCI 归档，以同一执行权验证实际内容。确认归档字节，提交唯一 Registry 意图，然后调用已批准来源与仓库的导入接口。导入前后再核对执行权，转移给结果核对时保留当前操作。
2. 结果未知或过程丢失执行权时，仅保留已发生的持久化事实。旧进程无法结算。新进程从待核对队列领取后调用只读 Registry 接口，同一意图不会再次触发导入。受保护部署仍以实际 Komodo 派发和线上验证为最终闸门。
3. 原生探针负责验收当前阶段。真实 OCI 导入后，在清理暂存且确认记录尚未写入前终止 Worker。新 Worker 不接收旧暂存且使用独立只读证据接续。另验证丢失结果、目标不符、无授权和取消。

## 验收

- 真实 PostgreSQL 验证任务状态、排他环境、全局执行权、新唤醒和过期 Worker 隔离。日志绑定同一候选与同一操作。
- Registry 导入意图提交及首次外部写入只能发生一次。对未知结果只作有限的独立查询，所有未确认结果保留明确的待核对状态。
- 真实 KVM 归档与实际 Registry 核对同一摘要，并证明进程中断前后的步骤记录和不重复导入。保留双语事件、固定源码、测试运行及 Review Guide。
