# P4-D2b3 · 审计 Agent 引用已发布代码规则

本批把任务留存的规则检查回执接入受限审计工具及最终清单。 [#149](https://github.com/MaLaNg116/itervane/pull/149) · [正式规则检查计划](p4-formal-published-inspection.md)

1. 仅当任务回执具备当前固定快照的规则检查证据时，向 ReAct 审计开放 Semgrep CE 观察。Gitleaks 和 Trivy 仍是必读项。扫描结果提供匹配标识、规则键、受限定位和覆盖范围，原始源码、规则表达式及审计模型的路径访问由现有边界约束。
2. 审计完成前要求引用所有适用扫描证据和对应发现。历史运行沿用既有两项扫描，含规则检查的任务在重领后复核原凭据及引用。规则匹配与业务影响分开记载，仍未支持模板处理的规则发现进入人工核对。
3. 双语任务页在现有项目权限下展示规则发现和证据。用真实 PostgreSQL 走通模型读取、清单写入、命中后的人工状态、早结束缺证和旧任务回归。模型采用受控协议夹具，真实 KVM 扫描证据另有固定工件。

后续批次在独立复验对同一规则集进行重扫，绑定候选源码和发布资格。第二个登记项目仍需使用真实发布记录完成复用验收。
