# P2-E-D3-D · P2 真实发布端到端验收

接续 [双语发布结果 #59](https://github.com/MaLaNg116/itervane/pull/59)。每次验证都把外部 MCP 任务、冻结候选、人工确认、Registry OCI、Komodo 原生更新、运行镜像和入口健康关联到同一发布操作。 [发布结算计划](p2-e-rollout-settlement.md) · [v6 蓝图](../blueprint-v6.md)

| 批次 | 验收证据 |
| --- | --- |
| D1 隔离部署目标 | 在专用托管主机创建带归属标记的内部桥接网络。Komodo 读取登记目标，实际容器仅加入该网络，保持无宿主端口绑定。收尾以标记核对并清理容器和网络。 |
| D2 同一真实操作 | 复用 KVM 标准应用和发布夹具。真实 MCP 发起审计，Runner 完成修改和独立复验。从当前代次的结果申请并确认冻结候选。启动安装态发布 Worker，核验真实 Registry、Komodo、Traefik、OAuth2 Proxy 和 Keycloak，保存 HTTP、MCP 与 PostgreSQL 的同一结果。 |
| D3 完整范围 | 至少两类可客观验证的问题各有闭环证据。审批后素材或目标漂移会中止写入，匿名访问、503、授权服务失联和进程中断均有对应观察及恢复证据。准入、审批、执行和释放绑定到同一操作。 |

普通与隔离 Runner 的既有验收继续保留。测试只在临时环境使用固定合成仓库和临时主体，登记的探测身份与批准主体分开。报告保留已校验的摘要、操作和结果，证据标识其模型模式。履行 P2 出口后接续 v6 的 P3 运维闭环。
