## 架构与交接

外层 LangGraph 管理角色、暂停与恢复，沿用锁定的 LangGraph TS 和 PostgreSQL checkpointer。内层每轮读取同一范围的结构化证据，由模型选择一个角色允许的工具或申请结束。实际观察进入下一轮上下文，工具与角色结果由严格契约验收。原始自由文本推理、未授权指令和 SDK 错误不进入检查点。工具输出和规则都被标为资料。参考 [LangGraph 工作流与 Agent](https://docs.langchain.com/oss/javascript/langgraph/workflows-agents) 和[持久化](https://docs.langchain.com/oss/javascript/langgraph/persistence)。

| 角色 | 允许的动作 | 交接及完成判据 |
| --- | --- | --- |
| 审计 | 按需调取固定源码片段、版本化指导、确定性检查摘要 | 有来源的发现、业务影响与修复建议、疑似和未覆盖项分别表达；缺可信观察时请求人工 |
| 修复 | 按发现选择已登记模板，生成与原始快照绑定的候选差异 | 保存模板、候选内容摘要、差异 SHA-256 和覆盖发现。普通非模板修改随后接受限 VM 工具 |
| 复验 | 在新上下文读取候选，调用受保护的重复扫描、平台基线与针对性检查 | 机器依据同一候选和基线的三类回执划分已解决、未解决、新增和未核验；模型负责说明。检查失败按预算返修或升级 |

所有观察绑定任务、run、项目、固定输入、规则与基线摘要。运行启动时固定语言、预算和截止时间。模型调用/工具前同步保存预留与已用次数，执行前后核对权限、时间和取消。恢复时核对逻辑范围和剩余预算，待核对的外部尝试保留预留并转人工。已确认边界可续跑。动作与证据重复、超预算、调用失败、输入不完整各有双语原因。实际用量返回后计费校验、调用次数与输出上限在发出请求前限制。

本次验收用独立 checkpointer 和固定可信样例验证重启恢复。生产接入须按 [ADR 0002](../decisions/0002-checkpoint-publication.md) 使用领域已发布的 checkpoint 与当前 fence；前置检查图状态不能直接当成交付图状态。批准、Komodo、运维 Agent、规则沉淀分别在 P2 后段、P3 与 P4 接入。

## 实施顺序和验收

| 顺序 | 需求提交 | 验收 |
| --- | --- | --- |
| A0 | 本计划 | 明确 D2/D3、资源映射及 P2 后续约束 |
| A1 | 复用 Anthropic/OpenAI 协议适配器 | 沿用原版本、轮次耗用及无重定向策略；官方 SDK 的 loopback 协议回归，P0 探针行为保留 |
| A2 | 引入任务、工具回执、角色交接和双语结果契约 | 拒绝错角色、错版本、伪造引用和模型自报通过；保留范围、覆盖、摘要和预算 |
| A3 | ReAct 图、上下文收缩、停止/取消、回执判断与返修 | 两组不同观察引导不同调用路径，限制同工具重试、调用计量和整体耗时，角色间不继承原始推理 |
| A4 | 固定样例与 PostgreSQL 恢复回归 | 真实差异和独立检查；回归候选不能通过；停在已确认边界可恢复，未确认调用不重复，双语和既有 API/MCP/Runner 闸门回归 |
| A5 | 运行说明、review guide、索引和草稿 PR | 保存固定代码、验收结果和未覆盖项，按需求点采用中文 Conventional Commits |

样例只处理仓库自身生成的有界数据，不连接真实执行或发布目标。可信样例测试、协议联调、真实模型试跑分别记录，均不能代替正式隔离复验和 P2 完整交付。
