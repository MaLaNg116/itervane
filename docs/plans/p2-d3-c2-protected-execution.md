# P2-D3-C2 · 标准应用的受保护检查与构建

依赖 P2-D3-B 的重放与复扫回执，以及 C1 准备的依赖缓存。先把维护者的标准应用检查拆成独立的可封存程序，再接入一次性 VM 的离线构建和应用启动。 [P2-D3-C 计划](p2-d3-c-protected-build.md) · [前置依赖 #26](https://github.com/MaLaNg116/itervane/pull/26)

## 执行顺序

1. 从已验证的原始或修复清单读取应用输入。工作副本归构建账户，原快照、候选、缓存、基线测试与运行配置分别封存。平台 profile 固定入口、依赖清单、工具和检查代码的摘要。
2. 在合格客体中离线安装依赖，关闭安装生命周期脚本，并使用平台指定的 Vite 构建入口。受限账户操作本次工作区，构建失联、超时或缓存缺项时保留原因和回收证据。
3. 受限应用进程运行候选产物。独立测试身份通过客体私有回环确认健康、版本、合成数据、页面及编译后的前端资源。禁止跟随重定向，限制响应大小和请求时间。测试代码及报告目录独立于应用，归一化结果不含原始响应。
4. 保留候选指纹、平台基线摘要、检查结果和清理回执。检查失败进入复验阻断路径；通过的输出由 C3 生成 OCI 镜像并扫描同一摘要，最终结果继续依赖后续交付。

## 分批验收

| 批次 | 交付 | 验收 |
| --- | --- | --- |
| C2-A | 可独立封存的标准 HTTP 基线 | 可信标准样例通过真实健康、版本、合成数据及静态资源检查。回归样例仍能服务其他路径时，健康门槛能识别失败。验证器只读取回环固定路径。 |
| C2-B | 合格客体的离线安装与构建 | 用固定源码和 C1 缓存在新 VM 安装、构建并保留工作树绑定，覆盖缓存缺失、版本替换和隔离拒绝。 |
| C2-C | 受限应用进程、基线证据与停止清理 | 同候选在 VM 执行独立的 HTTP 基线，验证健康回归、终止和清理，输出受保护记录供镜像阶段读取。 |

首次参考执行使用 Linux amd64 及维护者提供的 profile。项目代码、针对性回归和未信任依赖的实际安装、构建及运行继续使用合格的一次性 VM；标准样例的现有可信开发测试可复跑。
