# P5-C3 · 可复现的 v0.1 源码发布包

将参考安装整理为可核对的源码交付。以前置参考升级批次为比较基线。 [P5 发布验收](../implementation-plan-v2-ts-postgresql.md#p5-验证可靠性并形成可复现的开源交付) · [前置 #171](https://github.com/MaLaNg116/itervane/pull/171)

1. 从一个已提交且工作区干净的 Git 版本生成源码压缩包、安装依赖的许可证索引、文件校验值和版本清单。沿用冻结锁文件。发布包包含项目源码与许可声明，安装时从各上游获取第三方包、镜像与工具。
2. 整理双语发布与组件说明。列出生产与参考拓扑使用的图像和工具版本、摘要来源、声明的许可证、两个模型协议的配置，以及内置规则与用户导入规则的许可范围。GSAP 与 shadcn 继续按各自条款使用。
3. 托管任务在同一工具链上连续打包两次并逐文件比较。从解包后的独立目录冻结安装、构建门户并在真实 PostgreSQL、Keycloak 和 Chrome 上登录、调用 MCP。只保留版本清单、校验值、许可证索引、源码包及脱敏回执。
4. 待故障、并发、备份、三条闭环及发布报告齐备后，使用已合入的最终源码生成正式发布资产。源包构建与发布证据分别校验，发布时以最终代码树为准。
