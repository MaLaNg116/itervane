# P3-C2c3 · 重启恢复核验与结算

#96 已把首次及续发意图写入 PostgreSQL，并保存下游回执。恢复证明同时覆盖同一容器的新启动、冻结镜像和实际受保护入口。继续沿用 [重启执行计划](p3-c-whiskers-restart-execution.md) 与 [v6 蓝图](../blueprint-v6.md)。

| 批次 | 交付 | 验收 |
| --- | --- | --- |
| C2c3a 恢复证据 | 经 Komodo 只读检查取得已发布的同一容器在停止态的启动锚点。后置核对复用 Komodo、Traefik 和 Keycloak 的发布观察，要求同一实例启动时间推进、冻结镜像及运行配置一致、匿名访问被拒、授权健康返回已验证版本。 | 精确校验时间、容器、网络、版本和入口，含漂移及遮蔽回归。固定 Komodo 版本验证同一受控容器的停止与恢复读回。 |
| C2c3b 持久化结算 | 发送前在同一意图事务固定停止快照，续发复核原快照。后继只读租约关联实际操作、原生批准和同一发布。证据与任务状态原子提交。 | 真库核对过期 fence、撤权后读回、重启证据冲突、重复结算与环境占用。已证明恢复且原生许可已结清才释放环境。未知提交或证据不足保留环境占用，有限次核对后明确转人工。 |
| C2c3c 安装与原生闭环 | 专用执行 Worker 使用限定 Whiskers 写资格和限定健康读取资格。门户沿用人审入口，已确认的原生请求经本人续发，门户和 MCP 查询脱敏双语回执。 | 同一已发布标准应用在真实后端完成故障、平台审批、原生确认、一次派发与独立健康核验。同步验证暂停、回执丢失、过期及撤销后的只读处置。正式开关依赖本批证据。 |

恢复时优先读取同一 Docker 引擎提供的两次启动时间，按精确实例和已授权映射关联。后置核对期间实例、时间或入口发生变化即结束本次核验。健康探针沿用冻结目标和凭证约束，回执保留结构化事实。

平台批准撤回后只读取原操作效果，读取范围由历史操作和受信安装共同限定。只看到运行健康时仍需要确认原生许可的状态。无法安全核对的环境交给人工处理。C2d 的指定版本恢复及 C3 的异常触发和关联修复继续按计划交付。
