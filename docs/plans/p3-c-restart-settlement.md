# P3-C2c3b2 · 独立核对与重启结算

接续 #98 的停止快照。核对使用已有的 `reconcile` 调度和新的执行租约，读取受信安装所对应的原发布效果。读取上下文绑定原提案、已验证发布、登记、容器与停止快照，平台批准撤销后仍可在同一范围只读核对。 [恢复核验计划](p3-c-restart-recovery-evidence.md)

| 证据 | 处理 | 环境占用 |
| --- | --- | --- |
| 独立恢复成立，且原续发确认了同一原生批准的一次执行 | 事务提交核对记录、任务成功、环境释放与执行槽清空 | 释放 |
| 恢复成立但原生许可的结果未知，或目标、登记及历史证据已不匹配 | 持久化可用证据与原因，任务转人工 | 保留 |
| 读取暂不可用、应用仍未恢复或核对 Worker 的租约到期 | 最多三次只读核对，每次使用新 fence。耗尽后持久化人工处理状态 | 保留 |

恢复回执绑定原生调用摘要、停止快照摘要、发布 ID 和核对 fence。已应答的原生许可还应关联已保存的原批准 ID 及续发序号。每次核对的起始、结果和唤醒以 PostgreSQL 为准。读取中断和回执不明均沿用既有单工具写入边界。

验收使用真实 PostgreSQL 验证重复投递、恢复后发布准入、撤权后的同范围读取、健康成立但原生结局未知、登记漂移、过期 fence、失败重领、三次上限及失败注入后的原子回滚。保留英文及简体中文事件。正式安装、门户续发、回执查询及同一应用上真实 Whiskers 完整链路接续 C2c3c。
