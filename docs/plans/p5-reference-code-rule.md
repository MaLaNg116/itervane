# P5-B7 · 在干净参考安装中提炼并复用代码规则

用真实应用健康故障及关联修复生成代码规则案例。沿用参考控制面、正式 Keycloak 身份、固定输入 KVM Runner 和受保护部署。下一项目的正反用例经过不同虚拟机的实际检查。 [参考开发](p5-reference-release.md) · [参考 Runbook](p5-reference-runbook.md) · [P4 已联验的代码规则](../reviews/p4-native-rule-reuse.md)

1. 复用原生关联修复场景中的固定故障和修复坐标。为参考安装配置独立的标准 Web 构建及 Semgrep 输入，保留同一镜像的扫描、构建、OCI 和样例指纹。在该安装进行真实发布观测、健康事件、诊断和关联修复。保留原始故障证据与修复后独立复验，不用依赖修复案例推导应用健康检查。
2. 用修复结果保存恢复案例。正式提炼 Worker 生成针对该现象的代码规则，真实 VM 运行命中、修正和相似样例。复用参考门户的来源、适用范围和验证证据审核，发布后保留激活和版本。
3. 在第二个登记项目分别提交固定的命中与干净版本。核对规则版本快照、原生 Semgrep 汇总、审计引用、发布闸门和独立复验。命中任务停留等待人工，干净任务复验后可生成同一规则版本约束的候选。
4. 保留完整托管回执，并纳入 P5 发布审计。开发与运维各三次独立运行继续由对应参考作业核对，代码规则场景独立记录源案例、目标作用域、模型和执行资源。
