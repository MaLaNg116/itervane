## 2. 完整 Runner 设计

复用 QEMU/KVM、libvirt 和 Git，不自研 hypervisor 或集群调度。VM 控制器与 API/Worker 权限和进程分开；Agent 只看到结构化、绑定任务/项目/固定版本的工具，没有宿主 shell、Docker socket、libvirt socket 或基础设施凭证。

完整路径：`当前领域授权/执行权 → 固定检查计划 → 控制器核验隔离证明与任务租约 → 新 VM → 限定仓库源获取 → 验证 commit/tree/文件 → 断开源码外网 → 受保护扫描器/配置/数据库 → 有界产物 → 领域 fencing 发布 → VM 销毁及清理回执`。

- 镜像绑定不可变 digest，工具/配置/漏洞库记录版本和内容哈希；不能通过配置 verified=true 自证隔离。
- 控制器证明至少包含实测 KVM、镜像、网络拒绝、宿主/跨任务不可达、停止/残留测试及证据版本。缺任一项保持阻断。
- 默认两个 vCPU、2 GiB RAM、8 GiB 临时磁盘和有界时限；真实限制仍需 D2 验证，D1 只表达所需约束。
- 获取仅支持登记 HTTPS 源，未来需出口代理/允许域名、DNS 重绑/重定向/IP 范围验证，阻止元数据和内网探测；凭证由受管引用注入获取阶段，不写入计划/日志/checkpoint。
- 获取和 Git 对象解析均在 VM 内。固定完整 commit，不读取分支 latest，不运行 hooks/smudge/LFS/submodule，不安装依赖或执行 package scripts。扫描阶段无网络；漏洞库由可信准备流程导入。
- 受保护扫描配置、空忽略清单、工具和检查基线不来自项目目录。源码只读，产物单独限额；原始报告不进入普通日志或领域表。
- 执行前/发布前检查权限、generation、fence、预算和取消。控制器独立 TTL 负责丢失 Worker 的停止；恢复先查原 VM/作业状态和清理回执，不盲目再开 VM。
- 取消/超时实际停止进程并销毁 VM后才能确认清理；结果未知时标记核对中。D1 不提供假控制器、成功回执或生产调度入口。

## 4. 源码与证据约束

本次快照校验器只处理调用方提供的有界文件字节和原始 commit 字节，通过重新计算 Git 对象图证明内容匹配请求的完整 commit。它不会 fetch、checkout、解压或执行源码，也不验证仓库所有权/提交签名。生产端如何安全获得这些字节仍由 D2/D3 完成。

首批只支持便携相对文件路径和普通文件/可执行文件位；拒绝绝对路径、反斜线、`.`/`..`、元数据目录、大小写碰撞、重复路径、文件/目录冲突、symlink、gitlink 和未物化 LFS 指针。限额初值：5000 文件、单文件 2 MiB、总内容 32 MiB、commit 对象 64 KiB。超限明确不支持，不能跳过文件后报告干净。

扫描报告绑定 manifest/source、工具版本、受保护配置和所用数据库证据。Gitleaks 负责固定快照中的密钥模式，Trivy 首先支持 npm package-lock 的已知漏洞；PII、运行时鉴权、业务逻辑及完整 Git 历史不是它们的覆盖范围。无发现不等于安全通过，更不等于发布资格。

漏洞库缺失、过期、来源不可确认或扫描器失败不能归为“零漏洞”。数据库更新时间/内容哈希与 scanner 状态分别保存；扫描器归一化不是人工判定的替代。真实泄露处置仍需要持有者撤销或轮换密钥。

## 5. 当前机器可验与不可验

| 当前可验 | 仍受 KVM/后续集成阻断 |
|---|---|
| 严格契约、纯内容校验与真实 Git 对照 | 任意提交仓库的安全获取、checkout 和扫描 |
| 官方 CLI 对维护者生成合成文件的实际行为、报告脱敏/缺库失败 | VM 边界、宿主/其他任务隔离、真实网络出口与 DNS 拒绝 |
| 真实 PostgreSQL 的计划原子性、竞争、权限和 fencing | VM 创建/销毁、资源/超时/取消/进程树、残留验证 |
| API/MCP/中英文门户读取同一正式准备记录，当前任务继续等待 | 已验证快照和扫描证据在真实任务的受控发布 |

Docker 只承载可信 PG/Keycloak；本机 CLI 只扫描维护者生成的固定合成样例，不能接收路径/URL 参数扫描任意项目。CI 通过只证明 D1，`sandbox/taskExecution/sourceSnapshots/sourceScanning` 仍为 false。完整 P0、P1、MVP 不验收通过。
