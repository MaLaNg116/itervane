# P5-C5 · 最终源码版本的发布验收

将 P5 的发布判据对应到同一 Git commit 的托管结果、原生回执和可复现源码归档。以前置参考评测批次为比较基线。 [P5 实施计划](../implementation-plan-v2-ts-postgresql.md#p5-验证可靠性并形成可复现的开源交付) · [前置 #173](https://github.com/MaLaNg116/itervane/pull/173)

1. 记录回归矩阵与固定用例，覆盖模型循环、任务和检查点、人工审批、下游结果未知、并发及隔离。托管 Verification 保留真实 PostgreSQL 用例数与运行范围，缺少或失败的证据保留原状。
2. 核对同一仓库、同一源码 commit 和代码树的 Verification、Native Runner 和 Source Release。要求工作流及其发布判据通过，同时核对三次独立开发和运维、规则与 Runbook 复用、指定版本恢复、冷备和保护入口、升级及归档重装回执。
3. 生成可随源码资产保存的脱敏验收汇总。汇总带实际运行链接、固定镜像和依赖来源、质量和资源报告。单独保存授权模型探测的覆盖结果。根据实际签出和托管结果完成发布审查，保留每个 PR 的导读。
4. 参考复验失败时记录最后可见的任务状态、复验状态和有限事件代码，便于区分执行阻断和等待超时。沿用原有成功条件、等待上限和清理流程。
