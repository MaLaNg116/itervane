# P2-E-C3-C · 发布步骤记录与 Registry 恢复

基于正式发布认领，贯通已批准归档、真实 Registry 和可恢复的发布步骤，交给后续 Komodo 派发。 [PR #47](https://github.com/MaLaNg116/itervane/pull/47) · [P2 发布验收](p2-e-formal-release.md) · [v6 蓝图](../blueprint-v6.md)

## 执行边界

| 步骤 | 持久化事实 | 恢复动作 |
| --- | --- | --- |
| 读取冻结归档 | 按操作和当前 fence 保存读取准备与实际字节的摘要、长度和 Runner 证明 | 每次新租约重新获取所需字节，只以同一冻结归档的本次确认作为写入前提 |
| 写入 Registry 前 | 在有效的人工批准、操作、环境和 fence 内提交唯一导入意图，绑定冻结目标版本、OCI manifest、配置和已独立核对的归档 | 已提交意图的操作始终保留环境占用。恢复者以受限凭证读同一不可变地址 |
| 独立确认 Registry | 持久化实际回读的 manifest、配置和镜像引用。状态需同一操作和有效的结果记录权，事件随状态提交 | 核对相同来源、仓库、摘要和实际返回字节。无足够证据时显示待核对，同一操作保留原始证据与环境占用 |

归档和 Registry 是两个固定步骤。归档的重复读取按 fence 记录，Registry 导入意图对同一操作唯一。步骤表绑定操作与原始 fence，保留当前核对的状态及记录人。任务事件记录关键跃迁，绑定候选指纹与人工决定。凭证、暂存绝对路径和后端错误原文不写入持久层。

## Worker 与恢复

1. 归档读取前和交接时核对正式执行权与审批。使用已有受保护 Runner 通道。新租约不继承上一个进程的暂存；实际传输、核验与清理沿用 C1。工作区内的应用代码继续使用合格的一次性 VM。
2. 同一事务内核对当前 fence 的归档凭据、授权、目标和 Registry 来源，再记录明确导入意图并推进运行阶段。导入前再次核对执行权。导入使用已批准的固定 digest 和现有适配器的独立 Registry 回读。无实际回读证据时，状态进入待核对。
3. 中断时按是否存在已提交写入意图区分恢复。无意图时可为同一操作重发正式唤醒。已有意图时保留环境占用，切到正式待核对阶段并以新 fence 恢复。新的 Worker 读 Registry 的实际状态，已有同摘要结果可登记确认；超时、缺失或错配保留证据不明状态与可重复查询的入口。恢复者只继承与该意图绑定的只读核对权；待核对操作不会重放导入，也不获得新的派发权。
4. 用户取消或审批失效会让后续写入停止。已提交意图仍需经过只读核对，并记录取消或升级人工的结果。确认 Registry 后，后续 Komodo 派发单独重验授权和目标，沿用同一操作及固定镜像证据。

全局执行槽的争用和恢复沿用 C3-B。上游源码队列不领取发布中的任务。已核验 Registry 允许交给 C4，发布 capability 仍按 P2 真正上线核验后放行。

## 分批交付与验收

| 批次 | 交付 | 验收 |
| --- | --- | --- |
| C3-C1 | 只读 Registry 核对接口、带 fence 的步骤记录和查询契约 | 真实 PostgreSQL 拒绝跳过归档、跨操作证明、陈旧记录与重复导入意图。真实临时 Registry 回读缺失与同摘要证据，错误来源及内容不足不产生成功证明 |
| C3-C2 | Worker 接线、待核对恢复、实际导入与中断复跑 | 从真实批准候选读取并验证归档，写入 Registry 后失去执行权，再用同一操作与新 fence 只读完成确认。缺失或错配保持环境占用。验证取消、撤权、重复队列及移交，留存双语事件和固定版本证据 |

每批保存 Review Guide、运行源码及验收链接。C4 接入正式 Komodo，E-D 独立核对运行镜像、配置、受保护入口和健康。
