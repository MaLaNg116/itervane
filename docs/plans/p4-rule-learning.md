# P4 · 从案例形成可复用的 Skill、规则和 Runbook

规则生命周期归 Itervane 控制面。使用 PostgreSQL 保存来源、不可变版本、验证回执、人审决定及应用记录。沿用五种角色、现有 ReAct 运行机制、双向 MCP 和独立 Runner。 [蓝图 v6](../blueprint-v6.md) · [实施计划](../implementation-plan-v2-ts-postgresql.md#p4-完成-skill规则和-runbook-的验证发布及后续复用) · [运行闸门](../decisions/0001-development-and-runtime-gates.md)

| 批次 | 依赖与交付 | 验收 |
| --- | --- | --- |
| A1 设计 Skill 草稿 | 依赖 P1 身份与 PostgreSQL。所有者按工作区或项目导入双语元数据、`SKILL.md`、参考文档和声明式设计资源。记录来源、授权代次、审核状态、版本及摘要。 | 严格校验附件类型、路径和大小。重复提交同版本及内容返回原记录，变更内容须新版本，数据库拒绝覆盖历史。跨项目授权、事务回滚和重启后读取走真库。 |
| A2 审核与版本账本 | 在 A1 基础上加入候选清单、验证来源、公开范围、当前版本指针和回滚事件。发布或回滚由门户所有者按版本、摘要、验证回执和当前授权确认。 | 重放、陈旧版本、过期授权及并发发布有确定性结果。草稿与已发布索引使用各自范围，历史引用稳定。 |
| B 案例与提炼 Agent | 读取已核验的 P2 交付或 P3 运维任务。保存脱敏案例与来源摘要。提炼角色可查询同类案例和规则，决定保留案例或提交结构化的代码规则、Runbook 和样例。 | 固定正反轨迹验证证据引用、重复识别、Agent 预算和权限失效。使用两个实际结算案例运行提炼。 |
| C 验证与正式发布 | 代码规则使用自行编写的声明式 Semgrep CE 规则，在一次性 VM 上跑违规、已修复与易误判样例。Runbook 使用现有工具目录及恢复判据，分别核对只读诊断与每个具副作用的动作入口。设计指导列出可自动检查与人工核对的条目。 | 保存执行方式、检查器版本、样例和结果摘要。失败与不确定进入人工复核。所有者确认后指针原子推进，规则包内容无法改变审批与执行权限。 |
| D 后续复用 | 正式任务启动固定适用库版本和发布事件。审计 Agent 查询已批准的设计指导，Runner 对固定源码执行获批规则；运维 Agent 把匹配 Runbook 接入提议、审批、已有执行与独立结果核对。 | 第二个项目命中代码规则，正常反例通过。后续真实运维任务按同一 Runbook 走实际处置和复核。回滚或强制撤销影响新任务及适用的现有授权，旧任务仍可追查原始版本。 |

包内容采用结构化版本和定界文本。主文件为 `SKILL.md`，参考文档保存在 `references/`，设计资源首版采用 `assets/` 下的 JSON 文档。导入事务保存文本数据和摘要。后续模型读取时将指导放在证据上下文中，由固定工具目录约束具体动作。 [Semgrep CE 规则格式](https://docs.semgrep.dev/writing-rules/rule-syntax) · [样例验证](https://docs.semgrep.dev/writing-rules/testing-rules) · [许可证](https://docs.semgrep.dev/licensing)

## A1 实施顺序

1. 定义版本合同与路径、容量、文本约束，固化包标识、作用域、双语元数据与内容。附件排序和换行规范化后计算 SHA-256。
2. 增加库和版本表，工作区与包键唯一，项目范围受复合外键约束。写入锁定包，所有者凭据及授权代次在事务中核对，版本和归档数据由数据库保护。
3. HTTP 接入草稿导入、分页摘要和指定版本读取。列表返回选定语言及版本摘要，详情返回原始文档。
4. 在真实 PostgreSQL 验证同版本并发、版本冲突、拒绝越界内容、权限撤销、写入回滚与只读历史。验收记录明确标记草稿资格。

现行正式扫描和发布各自继续读取固定基线。运行时库发布与复用按 A2 至 D 提供受管回执。 [P3 原生事件验收基础](p3-c-native-incident-interfaces.md)
