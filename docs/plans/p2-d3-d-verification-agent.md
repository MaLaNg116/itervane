# P2-D3-D-B · 基于正式证据的复验 Agent

依赖 [复验事实 #33](https://github.com/MaLaNg116/itervane/pull/33)，复用同一套 LangGraph 能力和 PostgreSQL 检查点。保留 D-C 的 Worker 状态转移和返修编排边界。 [D 阶段计划](p2-d3-d-formal-verification-agent.md)

1. 为正式复验注册独立角色作用域和只读工具。Agent 选择读取源码复扫、构建或 HTTP 基线。基线通过后可以继续查看同一候选的镜像、扫描及制品。已观察到回归时可在引用具体检查事实后给出返修建议。
2. 完成结果固定当前候选、输入和回执。已解决、未解决及新增问题总数，失败与未验证项均来自事实。Agent 提供有证据编号的说明与建议，发布资格仍由平台和人工审批核对。
3. 复用现有轮次、工具、token、时间、上下文、取消和无进展限制。恢复时校验冻结范围与每份观察的内容身份。正式 Worker 通过当前租约发布和读取本角色专用检查点。
4. 分别用基线通过及 503 观察验证后续工具选择。覆盖错误引用、未授权工具、重复调用、代次变化、重领续作和权限撤销。中英文提示与结束反馈同步。

本批的真实模型试验使用托管 Runner 留下的受限事实。完整业务调度、受控返修及门户和 MCP 读面分批验收。
