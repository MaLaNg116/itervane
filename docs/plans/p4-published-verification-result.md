# P4-D2b4b · 比较已发布规则并裁决正式复验

本批把独立 Runner 的规则观测接入正式复验与发布资格判断。 [#151](https://github.com/MaLaNg116/itervane/pull/151) · [Runner 复验计划](p4-qualified-published-verification.md)

1. 从任务已验证的正式检查回执读回固定的规则快照和规则版本，在复验执行权下构造同一份规则集。发布目标可以是固定原稿或已封存的修复候选。工具画像与结果绑定，服务重启后按原输入及清理回执恢复。
2. 比较原检查与独立复验。规则集合、语言覆盖和引擎不一致时记为不可验证，命中按规则和文件计算新增、已解决及剩余项。与既有 Gitleaks、Trivy 结果共同决定复验结论。发布前从持久化原始证据重算比较，保留既有人工审批和执行权。
3. 使用真实 PostgreSQL 验证无规则历史、缺失或失败的规则复验、真实回执形状的干净源及新增问题，记录审计到发布资格的结果。真实 KVM 的第二登记项目验收随后实施。
