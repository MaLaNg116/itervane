# P3-C2c · Whiskers 原生确认与恢复核验

基于 #90 的处置租约和 #91 的时钟修复。平台审批、Whiskers 原生审批和恢复证据各自留痕，关联到同一冻结提案、目标发布和处置任务。 [操作计划](p3-c-operations-execution.md) · [租约导读](../reviews/p3-c-operations-execution-intent.md)

| 交付 | 验收 |
| --- | --- |
| C2c1 原生申请绑定与暂停 | 发送前在原处置意图事务中冻结 Whiskers 来源、工具、全长容器参数与专用凭证指纹。回执只能由同一有效 fence 为该申请记录一次。记录批准 ID、追加双语等待事件、释放全局执行槽一并提交。该环境继续受处置占用。 |
| C2c2 受限派发与续发 | 在通过原生 Confirm 验收的专用安装上使用当前有效的登记策略和 Write 凭证。首次派发与经人工触发的续发分开保存意图。续发核对原批准 ID、参数、执行权和当前平台批准。安排有限次数，同一原生待批回执进入等待，换号或响应不明进入只读核对。 |
| C2c3 恢复核验与结算 | 结合已发布容器、启动时间变化、镜像及入口检查独立确认恢复。审批超时、撤权、实例漂移、传输中断和健康失败都产生可核对的结果。未知期间保留同环境互斥，清晰转人工。 |

Whiskers 0.15 的原生许可按调用者、工具和规范参数绑定，批准后的许可有效期为十分钟。参考安装限定专用调用身份和 Confirm 策略，续发前仍按平台当前授权和提案有效期检查。批准 ID 是关联证据，执行许可仍由 Whiskers 现场裁定。 [原生执行护栏](https://github.com/LupusMalusDeviant/Whiskers/blob/e10cfa62ed8c3129302f68e0b4ec6e3ece8994e4/src/Whiskers/Services/Agent/Guardrails/DirectMcpCallGuard.cs)

C2c1 用 PostgreSQL 17 验证绑定变更、旧 fence、重复回执、暂停提交失败与发布互斥。平台批准撤销时，已到达或随后到达的原生回执进入只读核对。实际执行启用前，以同一个已发布的合成工作负载复验平台批准、原生审批、调用、健康、取消及恢复。保留 Worker 的独立执行边界、现有双语界面与后续指定版本恢复计划。

## C2c2 续发入队与执行边界

C2c2a 从 #92 的原生回执和任务暂停继续。当前平台批准者以门户身份提交一次续发请求。请求引用已记录的原生批准 ID、调用指纹和处置任务版本，使用既有 PostgreSQL 唤醒。发送前复核当前授权、提案和安装目标，确认同一专用凭证并持久化本次发送意图。

| 情形 | 验收 |
| --- | --- |
| 重复或过期的续发 | 相同请求复用一次入队结果。旧任务版本、错误原生绑定、撤销、过期或失权在发送前阻断。 |
| 等待原生批准 | 原生后端返回同一批准 ID 且明确待批时释放全局槽，保留环境占用。一个原生批准最多接受三次由人发起的续发。 |
| 执行器中断或响应不明 | 领取后、写入发送意图前可以重领同一续发。发送意图落库后，后继执行器进入只读核对。原生应答也转入核对，由 C2c3 验证恢复。 |

C2c2b 将这些入口接到真实 Whiskers 适配器，逐次核对签发 Write 凭证的安装和运行中的 Confirm 策略，并使用原生人工批准验证只执行一次。C2c3 接入独立健康核验后完成整条处置链验收。

## C2c2b 固定原生策略与接入派发

C2c2b1 验证专用参考安装。登记实际运行版本、Whiskers 端点、服务与工具范围、写凭证指纹、启用的策略和安装代次。在同一个运行实例证明重启工具要求 Confirm，只有受信安装管理者能更改护栏，人工审批者使用原生 Operator 权限。Worker 在连接和发送前核对当前安装证明。策略未知、安装漂移或旧证明失效时阻止发送。 [原生策略管理](https://github.com/LupusMalusDeviant/Whiskers/blob/e10cfa62ed8c3129302f68e0b4ec6e3ece8994e4/src/Whiskers/Services/Agent/Guardrails/GuardrailStore.cs) · [原生审批角色](https://github.com/LupusMalusDeviant/Whiskers/blob/e10cfa62ed8c3129302f68e0b4ec6e3ece8994e4/src/Whiskers/Components/Pages/ApprovalsView.razor)

C2c2b2 接续处置调度和现有 `WhiskersRestartClient`。首次请求在平台批准、目标及安装资格全部有效时保存意图并调用一次。原生待批回执落库后暂停。门户批准人提交续发前，继续绑定原始原生批准与同一调用者。收到同号待批、执行回执、换号或超时，分别走原有等待或只读核对。门户及外部 MCP 保留各自的认证范围，Worker 使用专用 Write 凭证，Operator 通过 Whiskers 确认。

原生许可由调用者、工具和参数决定，跨处置复用相同身份时可能命中此前许可。任何已经可能发出的请求若仍有可用许可，保留同目标互斥。只有可信证据确认旧许可已消费、拒绝、过期或对应调用身份已撤销，才允许新处置使用相同绑定。验收覆盖撤销后迟到批准、首次请求命中旧许可的防护、无原生批准时无副作用和获批后仅一次调用。使用同一已发布的合成应用记录原生审批、调用和容器启动证据。 [原生许可生命周期](https://github.com/LupusMalusDeviant/Whiskers/blob/e10cfa62ed8c3129302f68e0b4ec6e3ece8994e4/src/Whiskers/Services/Agent/Guardrails/DirectMcpCallGuard.cs) · [原生请求有效期](https://github.com/LupusMalusDeviant/Whiskers/blob/e10cfa62ed8c3129302f68e0b4ec6e3ece8994e4/src/Whiskers/Services/Agent/Approvals/ApprovalStore.cs)

C2c3 提供独立恢复结算后再启用正式写执行，支持中英文状态并保留统一审计关联。

## 专用安装代次与环境登记

#94 已验证原生权限资源、固定策略和 Operator 审批。下一批将装机材料与运行资格接入同一登记。安装者固定 Whiskers 版本、实际入口、原生角色映射与 Confirm 策略，并为每个安装代次生成仅可调用重启工具的独立 Write 凭证。参考运行实例只给 Operator 提供交互登录，角色与护栏由安装者提供，人审会话无法改写这些配置。策略、登录边界或入站端点变更时创建新代次并撤销旧凭证。 [原生验收导读](../reviews/p3-c-whiskers-writer-scope.md)

受保护环境的写安装登记关联当前只读登记、安装代次、入口、服务器、策略摘要与写凭证指纹。每个环境至多一个活动写安装，历史凭证指纹保留以阻止重复启用。轮换写凭证时保留原只读登记及其摘要，已在核对中的任务可继续追踪同一发布。旧登记退出平台写权限，原生许可关闭仍以 Whiskers 的确认或可信撤销证据为准。

Worker 加载受信安装证明，事务内匹配当前登记、处置提案和租约，并在同一 Whiskers 连接中核对该 Write 凭证的实际工具范围。真实验收覆盖同一端点的新代次拒绝旧凭证、只读登记平滑升级、环境及策略指纹不匹配被阻断，以及原生证明和平台记录的一致性。后续由派发与结算阶段接续真实工作负载的首次和续发执行。
