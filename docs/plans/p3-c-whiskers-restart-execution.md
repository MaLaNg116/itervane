# P3-C2c · Whiskers 原生确认与恢复核验

基于 #90 的处置租约和 #91 的时钟修复。平台审批、Whiskers 原生审批和恢复证据各自留痕，关联到同一冻结提案、目标发布和处置任务。 [操作计划](p3-c-operations-execution.md) · [租约导读](../reviews/p3-c-operations-execution-intent.md)

| 交付 | 验收 |
| --- | --- |
| C2c1 原生申请绑定与暂停 | 发送前在原处置意图事务中冻结 Whiskers 来源、工具、全长容器参数与专用凭证指纹。回执只能由同一有效 fence 为该申请记录一次。记录批准 ID、追加双语等待事件、释放全局执行槽一并提交。该环境继续受处置占用。 |
| C2c2 受限派发与续发 | 在通过原生 Confirm 验收的专用安装上使用当前有效的登记策略和 Write 凭证。首次派发与经人工触发的续发分开保存意图。续发核对原批准 ID、参数、执行权和当前平台批准。安排有限次数，同一原生待批回执进入等待，换号或响应不明进入只读核对。 |
| C2c3 恢复核验与结算 | 结合已发布容器、启动时间变化、镜像及入口检查独立确认恢复。审批超时、撤权、实例漂移、传输中断和健康失败都产生可核对的结果。未知期间保留同环境互斥，清晰转人工。 |

Whiskers 0.15 的原生许可按调用者、工具和规范参数绑定，批准后的许可有效期为十分钟。参考安装限定专用调用身份和 Confirm 策略，续发前仍按平台当前授权和提案有效期检查。批准 ID 是关联证据，执行许可仍由 Whiskers 现场裁定。 [原生执行护栏](https://github.com/LupusMalusDeviant/Whiskers/blob/e10cfa62ed8c3129302f68e0b4ec6e3ece8994e4/src/Whiskers/Services/Agent/Guardrails/DirectMcpCallGuard.cs)

C2c1 用 PostgreSQL 17 验证绑定变更、旧 fence、重复回执、暂停提交失败与发布互斥。平台批准撤销时，已到达或随后到达的原生回执进入只读核对。实际执行启用前，以同一个已发布的合成工作负载复验平台批准、原生审批、调用、健康、取消及恢复。保留 Worker 的独立执行边界、现有双语界面与后续指定版本恢复计划。
