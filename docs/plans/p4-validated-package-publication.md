# P4-C3a · 已验证候选的审核与发布

接续 [#143](https://github.com/MaLaNg116/itervane/pull/143)，完成 [P4.4](../implementation-plan-v2-ts-postgresql.md) 的代码规则和 Runbook 发布链路。保留现有设计 Skill 的导入、历史摘要和审核流程。候选采集与样例验证继续使用其原有任务边界。

1. 工作区维护者通过已配置的人类门户身份选择一份通过的验证结果，明确版本、包标识、中英文摘要、来源、许可证及作用域。默认交互使用来源项目，工作区范围需显式选择。版本从原始提炼回执复制经过验证的正文，并绑定项目、提炼候选、验证结果及各自摘要。数据库核对正文与两份不可变回执。同一生成包标识的版本保持类型和作用域一致。
2. 沿用规则库的草稿、人工审核、发布、回滚和撤回账本。生成版本使用专门的验证证据审核项，摘要约束涵盖正文、来源和证据。继续检查当前维护授权，记录一次顺序操作，并保留旧版本和原审查记录。
3. 真实 PostgreSQL 验证两类通过候选、错误摘要、失败证据、跨项目选择、审核项混用、版本冲突、并发和回滚。托管场景验收正式来源案例经提炼和样例验证后能够人工发布。交付范围公开说明模型、身份和原生验证的实际覆盖。

双语门户操作接入 P4-C3b。P4-D 负责正式任务检索并固定版本、独立验证规则命中、按当前授权与审批执行 Runbook，以及核验旧任务快照与版本撤回。任何发布记录仅在规则库激活版本，运行权限仍由原有任务闸门授予。
