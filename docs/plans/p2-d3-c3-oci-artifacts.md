# P2-D3-C3-C · 已核验 OCI 产物交接

基于 [客体镜像和扫描 #31](https://github.com/MaLaNg116/itervane/pull/31)。正式复验可以在冻结输入中申请留存这次已扫描的 OCI。Runner 只交接同一 manifest 的完整布局字节，后续审批按这一内容地址发布。 [C3 计划](p2-d3-c3-final-image.md)

1. 在封存的客体镜像角色中以固定顺序归档已核对的 OCI 布局，绑定 manifest、归档 SHA-256、字节数和格式。应用和构建身份无权写入归档或回执。
2. 经同一受控 VM 会话返回回执及有界分块。宿主把归档当作不透明字节，在隔离暂存文件流式核对大小与摘要。提前断开、重复结束、摘要变更均丢弃未完成的暂存。
3. VM 清理确认且当前调用仍有效时，按 SHA-256 原子写入专用制品目录。重复相同字节去重，破损对象中止。浏览器、Agent 和外部 MCP 只接触获得授权的结果。后续获批发布按内容地址重新核对后交给镜像库。
4. 将留存证据绑定到请求、当前任务代次、执行权、OCI 和扫描摘要。重读沿用正式复验事务。受控取消后的孤立字节没有发布资格，验证任务已失效时不能获得新回执。

验收包括实际托管 KVM 传输、独立回读和重算 manifest 的同一性，另有取消、截断、摘要替换、重复写入和旧执行者的对照。仓库、Komodo 和个人凭证仍由此前的信任边界管理。P2-E 负责审批后的真实发布与运行版本确认。
