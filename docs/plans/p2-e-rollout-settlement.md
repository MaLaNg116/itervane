# P2-E-D3 · 发布核验与结算

接续 [正式 Komodo Worker #52](https://github.com/MaLaNg116/itervane/pull/52)、[运行回读 #53](https://github.com/MaLaNg116/itervane/pull/53)、[入口核验 #54](https://github.com/MaLaNg116/itervane/pull/54) 和 [自托管接线 #55](https://github.com/MaLaNg116/itervane/pull/55)。本批完成发布流程的最后一段，从已经记录的原生更新独立核对实际版本、访问保护和健康后才更新发布结果。 [P2-E 总计划](p2-e-formal-release.md)

| 交付 | 主要工作 | 验收 |
| --- | --- | --- |
| D3-A 只读核验权 | 给已派发且进入 `release_komodo_awaiting_rollout` 的操作单独签发有界核验租约。用 PostgreSQL 事务协调认领、fence、次数、到期和重领。认领绑定版本化目标、冻结候选、同一决策、环境占用和已记录原生更新。 | 两个核验进程只有一个获得同一操作的当前租约。进程停止可重领且消耗原有预算。持续保持环境占用，模型工作流的执行槽可用于其他任务。 |
| D3-B 最终证据 | 在一次核验内取得原生更新、实际容器、受保护入口和健康结果。提交时重新检查当前租约和各项不可变绑定，持久化脱敏证明、状态和事件。 | 真实 PostgreSQL 幂等、权限、过期、事务失败和竞争回归。空报告、错操作、错候选、错误镜像、失效租约和漂移无法结算成功。 |
| D3-C 正式 Worker 与双语读取 | 从安装侧加载目标对应的下游服务身份，接通受限执行和只读核验。通过同一任务和操作记录向门户及外部 MCP 发布双语状态。 | 未登记配置时维持闸门。门户、外部 MCP 和审计事件显示同一结果。确认、撤销、取消和状态恢复的现有规则在真实队列回归中成立。 |
| D3-D P2 端到端 | 用托管一次性 VM 构建标准应用，将同摘要 OCI 发布到真实 Komodo。通过已登记的 Traefik、OAuth2 Proxy 和 Keycloak 核对实际入口。 | 从真实外部 MCP 客户端发起，完成两类可客观验证的问题、独立复验、冻结、人审、发布和健康结果。真实测试覆盖审批后变更制品、受保护入口漂移、503、授权服务失联及进程中断。 |

## 证据与状态

- 只读证明绑定操作 ID、接受的决策和代次、候选指纹、目标映射修订、已记录的原生更新、容器 ID、已获批的镜像摘要、入口配置指纹和观测时间。实际部署和健康证明各自可复核。已有可信样例的 `verified_fixture` 状态按原语义读取。
- 原生更新成功、实际容器对应候选、入口受保护、健康响应正确这四点齐备时，事务才可写正式发布完成事件并释放环境占用。候选、授权和下游配置的不同步有可追踪的状态。
- 取消、撤权或批准过期会关闭后续写入。保留的已发生操作只允许有界事实上线核对，记录真实结果及当前任务处置状态。若结果未知、目标漂移或核验预算耗尽，保留环境占用并转人工。指定版本恢复按 P3 的独立审批和互斥规则接续。
- 客户端身份、Keycloak 服务账户密钥、完整的 HTTP 响应以及 Komodo 的原生容器资料留在各自服务层。持久化记录使用严格结构和受控原因码，门户继续共用现有中文、英文和权限机制。

测试使用独立 Runner、真实 PostgreSQL 与可信下游基础组件。发布端到端报告将冻结候选、实际部署与健康快照连在同一操作上。 [上线核验总计划](p2-e-rollout-verification.md) · [完整实施计划](../implementation-plan-v2-ts-postgresql.md)
