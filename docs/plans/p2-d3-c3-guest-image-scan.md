# P2-D3-C3-B · 同一客体组装和离线镜像扫描

基于 [固定 OCI 输入 #30](https://github.com/MaLaNg116/itervane/pull/30) 与现有受保护 HTTP 基线，封装并扫描实际标准应用。冻结输入显式绑定 OCI 输入回执摘要，沿用封存 VM、当前租约和候选摘要，独立控制器再校验镜像执行资格。 [C3 实施范围](p2-d3-c3-final-image.md)

1. 应用和探针退出后，读取已通过检查的运行目录。按固定路径封装 Node、后端、前端和生产依赖，去掉安装缓存等非运行文件。只接收有界的普通文件和目录，不将项目文件当作构建命令执行。
2. 封存配方用 umoci 创建 Linux amd64 镜像。入口、数字 UID/GID、平台和应用版本可核对。加层、配置和扫描均留在合格的一次性 VM。
3. Trivy 以 manifest digest 选择 OCI 布局，在离线模式覆盖系统包和实际安装的应用依赖。校对配置摘要、漏洞库、工具和回执。缺证或绑定变化分别保留阻断结果。
4. 本批原生验收检查实际健康候选、同一 digest 扫描、回执持久化重读和客体退出。HTTP 503 候选保留复验失败，缺包和锁漂移保留各自的阻断。C3-C 负责将已核验的镜像字节交给持久产物存储。
