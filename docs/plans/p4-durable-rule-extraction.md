# P4-B2b · 正式案例提炼、单槽执行与候选落库

接续 [#138](https://github.com/MaLaNg116/itervane/pull/138)。P4-B1 保存可核验的历史事实，B2a 定义第五种 ReAct 角色。本批让维护者从已有案例启动一项真实提炼任务，并在审批前取得可查询候选。 [P4 总计划](p4-rule-learning.md)

1. 启动接口核对项目、案例、摘要、现有权限及配置的模型指纹。在同一事务写入任务、运行、案例绑定和 pg-boss 唤醒。使用现有请求键重放。项目授权代次变化会阻止领取与续跑。
2. 首次占用全局槽时，从同项目、同类事实和已有候选固定查询快照。Worker 使用既有 LangGraph、模型协议及 PostgreSQL 检查点，检查点绑定案例、快照、模型和执行权。观察只读取已冻结数据，允许恢复；尚未结算的模型调用遵循已有中断策略。
3. 发布结果时独立重算案例、观察、检查点和候选语义，阻止过期 Worker 及重复语义写入。保存待验证候选或保留、重复决定，事务提交后才显示完成。HTTP 查询按项目授权与语言提供结算视图。后续 P4-C 验证和审核前，候选保持待验。
4. 真库验证并发入队、角色、模型配置漂移、执行权、复跑和重复。托管原生场景对真实修复与已批准重启案例分别生成候选，保留源码指纹、模型范围和固定依据。样例执行和下游使用在原定 P4-C 与 P4-D 验收。
