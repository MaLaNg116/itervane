# P2-D3-D-D · 正式复验结果与返修历史

基于 [正式 Worker 复验 #35](https://github.com/MaLaNg116/itervane/pull/35) 和 [受控返修 #36](https://github.com/MaLaNg116/itervane/pull/36)。业务方在任务详情和外部编码助手中看到同一个候选的独立复验结论。下一代尚在运行时，上一代的失败仍有可核对的记录。 [v6 蓝图](../blueprint-v6.md) · [独立复验计划](p2-d3-formal-verification.md)

| 批次 | 交付 | 验收 |
| --- | --- | --- |
| D-D1 查询契约 | 用同一个授权服务支持 HTTP `GET /v1/tasks/:taskId/verification` 和 MCP `get_verification`。对照任务、代次、结果、输入和 Runner 回执重建可公开给项目成员的复验证据。 | 两个入口返回相同的结构与证据引用。读权限、撤权、其他项目和 MCP scope 都有真实 PostgreSQL 测试。篡改或错绑的证据按查询失败处理。 |
| D-D2 门户展示 | 任务详情显示当前复验状态、对比数量、保护检查结果和镜像摘要。有返修时可展开上一代的正式证据。 | 中英文切换、状态更新、取消、查询错误及返修历史通过浏览器测试。沿用 shadcn/ui 组件和现有减少动效选项。 |

查询先验证当前项目读权限，再以任务代次确定当前 run。历史限于与当前 run 直接关联的返修记录及其上一代复验。每个结果的作用域、摘要和独立回执都需匹配。当前结果尚未形成时，呈现实际暂停原因或待复验状态。

返回值使用闭集状态、计数和有界证据引用。复验意见的自由文本、源码、补丁内容、原始 Runner 回执、执行授权和归档位置留在原有授权边界。前端沿用任务身份和轮询机制。

P2-E 独立负责候选冻结、制品发布核对和人工审批。D-D 的两个入口都只读取复验及返修信息。
