# P2-E-D3-D3 · 第二类修复与发布故障验收

从 [同一正式任务发布验收](p2-e-protected-release-workflow.md) 的入口扩展。固定样例的第一类修复移除合成敏感值。第二类修复使用 npm 公告和维护者精确批准，并从锁文件修复接续同一安装态发布路径。

| 批次 | 验收证据 |
| --- | --- |
| D3-A 依赖修复 | 以标准应用为基础，固定一份只含预期公告的旧依赖锁。维护者单独封存已修复的清单、锁文件和缓存，根据实际扫描确认批准版本解决发现。由 Agent 引用 Runner 观测的 npm 成对目标，经真实独立复验、OCI 扫描、人工批准和受保护发布。 |
| D3-B 批准和工件漂移 | 在确认后变更登记目标或留存工件，证明旧决定失效。核对候选和操作状态、Registry 未写入或停止继续写入、下游记录以及环境占用。 |
| D3-C 上线和恢复负例 | 保留匿名拒绝，验证同一实际应用的 503、授权服务失联及 Worker 中断。记录正式结果进入人工核验或有证据的恢复路径，核对未知更新不会触发再次派发。 |

两类修复都从固定源码与真实扫描证据开始。保留与修复对应的标准应用构建输入、软件成分与原生 KVM 记录。报告区分脚本模型、真实模型回放和控制面测试身份。第二类候选沿用首期只支持受维护者批准的两个 npm 文件改动，保留既有 OCI 阻断要求和真实出口。
