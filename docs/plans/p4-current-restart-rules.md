# P4-D4b · 规则变化后的运维执行与对账

本批把运维重启的当前规则核对扩展到任务最初没有匹配 Runbook 的情况，同时保留已记录的诊断、审批和效果回执。 [规则生命周期计划](p4-rule-learning.md) · [#157](https://github.com/MaLaNg116/itervane/pull/157)

1. 在重启提议、门户确认、领取动作和续办前比较任务固定的运维规则与当前适用集合。首次发布、换版和撤回均可需要重新诊断。PostgreSQL 核对新的批准与发送意图。版本恢复继续按自身的发布目标和批准判据执行。
2. 排队重启检测到新规则时在现有执行槽内关闭未发送的预留。已登记 Whiskers 审批或请求可能发出时，旧续办失效并转只读对账，保留环境占用及历史证据。状态和事件使用双语原因。
3. 用 PostgreSQL 验证空集合任务遇到首个 Runbook、批准后撤回、待原生批准的实例，以及不同时间到达的审批和执行。验证目标和权限既有故障路径继续有明确结论。
