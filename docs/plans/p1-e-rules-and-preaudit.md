## 1. 目标与阶段边界

编码助手和业务方能够查询适用规则/Skill，将限量文本提交预审，得到带版本、输入来源、位置和覆盖说明的可追溯结果。API/MCP/门户共用当前项目授权与领域记录，支持 en/zh-CN。

| 范围 | 本批交付 | 留给后续 |
|---|---|---|
| P1-E | 内置只读、可版本化规则/Skill；固定文本检测；片段/单文件文本 diff；脱敏持久化结果；双语 API/MCP/门户 | 无外部规则上传、任意正则/脚本、规则编辑或在线发布 |
| P2-A | 本批提供可检索材料、规则引用、机器结果与覆盖信息 | 自主 Agent 工具选择/反馈、模型/时间预算、上下文管理、无进展判断、角色交接与模型分析；本批不声称已实现 |
| P4 | 使用自带规则版本和来源作为未来输入契约 | Skill/规则包导入、样例验证、候选、人审发布/回滚、案例/Runbook 提炼与后续复用 |
| P1-D2/D3 | 维持 Runner 阻断与既有暂停 | 真实 VM、仓库获取、固定源码扫描、执行/清理/恢复证据；文本预审不绕过此门槛 |

不改三条闭环、五种角色、双向 MCP、单维护者/工作区/全局一个执行中工作流；完整 P1/MVP 继续未验收。

## 2. 最小功能

1. 内置少量自主维护的 Apache-2.0 材料，带 ID、版本、来源、类型、语言适用范围、内容摘要/哈希和中英文说明。区分文本检查、文字指导和 Skill；全部是 advisory，不自动成为发布阻断/批准。
2. 固定检查覆盖：eval 调用形态、HTML 写入/渲染危险入口形态、gitleaks:allow 文本标记；另有服务端授权指导和审阅上下文 Skill。模式命中不证明可利用；观察到标记也不证明平台强制扫描能被关闭。
3. 只接受客户端提供的片段或单文件 unified diff，语言为 javascript/typescript/json/text，限模拟或公开数据。上限 16 KiB UTF-8、1000 输入行、100 个观察；diff 只分析新增行，验证有限 hunk 结构和计数，不应用补丁或读取路径。
4. 结果记录输入 SHA-256/类型/字节数/行数、规则目录与引擎版本、规则内容快照/指纹、输入行及可得的新源码行、观察类别、覆盖限制。无命中使用 no_observations，不使用 clean/passed/approved。发布资格固定 false。
5. 片段仅在请求与处理内存中存在，不持久化源码/片段、摘要摘录、文件名、原始 diff 路径或请求体。规则与输出文本来自内置材料；保存的输入指纹不证明来源真实或匹配正式仓库。
6. 短请求同步完成，返回正式预审 ID；持久化元数据与报告在一个短事务中提交，支持跨 API/MCP 同键重试与重启后查询。它不入 Agent 队列，不占全局执行 slot，也不产生业务任务“已完成”。

## 3. 权限、隐私与版本

- 规则和历史预审查询需当前项目 read；创建持久化预审需 owner/maintainer，MCP 另需 read+write scope。只读成员不能通过预审 POST 写入。
- 请求必须固定 catalog SHA-256，并携带 UUID 幂等键。同主体/项目/键的语义输入一致返回原记录，改变片段、语言、格式、数据类别或目录版本冲突。
- 规则目录摘要绑定目录/引擎版本与内置检查定义；展示语言不改变语义输入。历史结果保存受信任的规则内容快照，后续目录更新不能重写原结果。
- 预审 POST 的 request body、临时文本和原始解析错误不进入日志/事件/checkpoint。客户端只保留组件内存中的待重试输入，不持久化，也不把原文作为 query key/mutation variables 保存；退出时卸载并清空私人状态。
- 输入始终作为数据处理；不使用 eval/Function/代码加载、AST 插件、模板执行、外部模型、网络获取、文件操作或 CLI。不能提交自定义 detector、regex、URL、脚本或 claimed approval。
- 规则查询的内容是有来源的指导材料，不具有覆盖平台权限、执行预算和审批的指令优先级；P2-A 必须继续落实这一分层。

| 单元 | 工作与依赖 | 验收 |

## 5. 验收与限制

完成路径：`登录 → 项目 → 查询规则/Skill → 固定目录版本提交有限文本 → 查看观察与覆盖 → 用同一 ID 经 API/MCP/门户重新查询 → 切换显示语言`。

单元验证实际固定文本行为，真 PG 验证事务/幂等/权限，浏览器使用真实 Keycloak 与数据库，MCP 使用官方外部 SDK。不使用模拟成功或模型自报结论代替验收。保留 P1-D1 的 Runner 关闭、原有任务恢复、真实 scanner fixture 和三组 Linux CI。

预审无法判断完整仓库、依赖漏洞、密钥有效性、PII、完整鉴权、运行时行为、业务逻辑或差异整体正确性；纯文本匹配可能位于字符串/注释内，必须明确其证据层次。未命中、不适用、指导材料、无新增行和截断都有可见覆盖说明。源码获取/执行与正式扫描、完整自主 Agent 和规则沉淀仍分别等待 D2/D3、P2-A、P4。

本地已通过 strict types、73 单元、66 真 PG、15 真 OIDC 浏览器及门户构建；按需求点分别提交。升级操作与接口见[运行说明](../control-plane-p1-e.md)，固定代码快照、阅读顺序和未覆盖事项见[review guide](../reviews/p1-e-rules-preaudit.md)。
