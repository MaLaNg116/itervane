# P3-C2d · 恢复指定已发布版本

接续 Whiskers 的重启核验。恢复由 Komodo 执行，平台绑定人工批准、已验证镜像、受保护环境和处置租约。后续诊断以独立读回的实际恢复结果为准。 [蓝图](../blueprint-v6.md) · [处置总计划](p3-c-operations-execution.md) · [前置 PR](https://github.com/MaLaNg116/itervane/pull/106)

| 批次 | 工作与验收 |
| --- | --- |
| C2d1 恢复依据 | 先确认当前实际发布，再找同一目标登记下最近已核验的不同镜像。跳过同一镜像的重复发布和旧目标登记。诊断与提案使用同一份历史核验依据。真库覆盖镜像重复发布、同范围授权、目标登记变化和一次正式确认。 |
| C2d2a 恢复意图 | 在已有处置租约下复核有效批准和当前目标，原子保存当前发布、批准恢复制品、其已核验版本以及 Komodo 目标。真库验证替换制品或目标被拒，事务失败时意图回滚，接管者只能读取同一记录。 |
| C2d2b1 原生只读核对 | 以独立 Komodo 读身份核对固定部署的配置与更新，按更新 ID、部署和原写入者绑定回执。用真实原生角色验证读取权限，验证异目标、错误操作人和写调用被拒。 |
| C2d2b2 恢复派发 | 在固定安装范围内先核对现行部署，再逐步发送配置变更与部署更新。每次发送单独消费当前租约和当前批准，记录独立配置读回或原生更新 ID。真库核对顺序、重复调用、撤权、结果丢失及接管。 |
| C2d3a 恢复核验 | 用独立读身份核对原生更新与受保护入口，留存已核验制品、实际运行镜像、版本和容器的回执。已知失败、未知更新和目标变化留给人工。对暂不可用和核验中断按代次限次重试。 |
| C2d3b 结算与当前版本 | 用已核验回执原子结算并释放环境占用。受控处置与诊断读取实际运行的恢复版本，将原正式发布和恢复核验事实保持关联。 |
| C2d4 参考环境联验 | 在同一应用上发布两个不同的固定镜像，批准恢复指定版本，核对后续诊断及门户与 MCP 的双语回执。复跑过期、撤销、目标变化、响应丢失和 Worker 接管场景。 |

C2d1 通过现有诊断、提案、人工审批服务验收。运行时恢复入口在恢复派发、结算及原生联验通过后启用。

配置发送前绑定当前实例和固定镜像，部署发送前验证同一执行代次的配置回执。发送授权先提交到数据库，再执行原生请求。接管可读取先前发送和已知回执。无论是否收到响应，已尝试的发送均进入核对路径。

恢复核验读取原生更新 ID、已批准制品和登记入口，并校验恢复容器与此前停止容器不同。收到完成更新并通过受保护健康核对后，回执带入结算。结算采用回执与当前版本登记的同一事务作为环境释放条件。
