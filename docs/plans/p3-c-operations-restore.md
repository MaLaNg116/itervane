# P3-C2d · 恢复指定已发布版本

接续 Whiskers 的重启核验。恢复由 Komodo 执行，平台绑定人工批准、已验证镜像、受保护环境和处置租约。后续诊断以独立读回的实际恢复结果为准。 [蓝图](../blueprint-v6.md) · [处置总计划](p3-c-operations-execution.md) · [前置 PR](https://github.com/MaLaNg116/itervane/pull/106)

| 批次 | 工作与验收 |
| --- | --- |
| C2d1 恢复依据 | 先确认当前实际发布，再找同一目标登记下最近已核验的不同镜像。跳过同一镜像的重复发布和旧目标登记。诊断与提案使用同一份历史核验依据。真库覆盖镜像重复发布、同范围授权、目标登记变化和一次正式确认。 |
| C2d2a 恢复意图 | 在已有处置租约下复核有效批准和当前目标，原子保存当前发布、批准恢复制品、其已核验版本以及 Komodo 目标。真库验证替换制品或目标被拒，事务失败时意图回滚，接管者只能读取同一记录。 |
| C2d2b1 原生只读核对 | 以独立 Komodo 读身份核对固定部署的配置与更新，按更新 ID、部署和原写入者绑定回执。用真实原生角色验证读取权限，验证异目标、错误操作人和写调用被拒。 |
| C2d2b2 恢复派发 | 在固定安装范围内先核对现行部署，再逐步发送配置变更与部署更新。每次发送单独消费当前租约和当前批准，记录独立配置读回或原生更新 ID。真库核对顺序、重复调用、撤权、结果丢失及接管。 |
| C2d3a 恢复核验 | 用独立读身份核对原生更新与受保护入口，留存已核验制品、实际运行镜像、版本和容器的回执。已知失败、未知更新和目标变化留给人工。对暂不可用和核验中断按代次限次重试。 |
| C2d3b 结算与当前版本 | 在同一 PostgreSQL 事务提交核验回执、成功事件和环境释放。保留原发布事实，用全局派发代次选择最近已结算的版本，使诊断、提案、确认、预约和重启共享当前实例。恢复绑定包含恢复执行 ID，旧发布绑定保持原指纹。真库验证 A → B → 恢复 A、旧批准失效、随后发布覆盖、未核验结果仍占用环境，以及结算缺项时事务回滚。 |
| C2d4 参考环境联验 | 在同一应用上发布两个不同的固定镜像，批准恢复指定版本，核对后续诊断及门户与 MCP 的双语回执。复跑过期、撤销、目标变化、响应丢失和 Worker 接管场景。 |

C2d1 通过现有诊断、提案、人工审批服务验收。运行时恢复入口在恢复派发、结算及原生联验通过后启用。

| C2d4 批次 | 工作与验收 |
| --- | --- |
| C2d4a 安装与队列 | 给指定版本恢复使用单独的持久化队列和 Worker，沿用全局执行槽及环境占用。装机绑定受保护环境、诊断登记、原 Komodo 写身份和独立读身份。真库验证队列分派、过期和撤销、丢失唤醒、旧队列数据迁移以及只读接管。 |
| C2d4b 人工入口与双语结果 | 由已确认的门户工作区所有者提交冻结提案，绑定批准代次和当前安装范围。门户与外部 MCP 查询同一处置的状态、已恢复版本与核验回执。测试安装缺失、身份变化、权限与旧实例失效。 |
| C2d4c 双版本原生联验 | 使用隔离 Runner、已登记的 Komodo 与受保护入口，在同一目标依次正常发布 A 与 B。验证 B 出现故障后恢复 A、匿名拒绝、授权健康、后续诊断和回执，以及真实响应中断和 Worker 接管。将固定版本的托管证据保存到评审导读后启用恢复入口。 |

| C2d4c 批次 | 工作与验收 |
| --- | --- |
| C2d4c1 同一目标双版本 | 新增独立的托管 KVM 场景。两个固定源码版本各自通过构建、镜像扫描、候选冻结、门户本人确认和专用发布 Worker。两次发布共用应用、环境、登记与受保护入口。主机独立核验两份 OCI 归档、实际容器与版本，确认历史依据只接受该目标的两次已核验上线。 |
| C2d4c2 原生指定版本恢复 | 在同一场景停止第二个版本，用 Whiskers 观察及内置运维 Agent 形成恢复提案。由原批准人确认并提交，由专用 Worker 向 Komodo 派发。独立读身份核对已批准的旧镜像、实际容器和更新，受保护入口返回授权健康与匿名拒绝。后续诊断读取已恢复的当前实例，HTTP 和 MCP 的中英文回执一致。 |
| C2d4c3 故障回归与参考安装 | 验证审批过期、撤销、目标变化、原生响应中断及只读接管。保留环境占用、全局执行槽和原生核对证据。固定版本验收后，将恢复入口接入默认关闭的自托管参考安装。 |

C2d4c2 复用 C2d4c1 的双版本托管场景。停止测试应用 B 后，实际 Whiskers 读取和运维 Agent 共同确认退出状态、当前 B 与候选 A。测试 API 通过已登记目标接通待验收的提交能力。记录批准前拒绝、原批准人提交、同一请求幂等和环境占用。恢复由独立进程从正式队列领取，使用 Komodo 写身份执行和固定 Read 身份核验。断言只有一项配置变更和一项部署派发，核验回执绑定原生更新、实际容器和健康检查。以中英文 HTTP/MCP 回执和下一次真实诊断验证实际恢复为 A，并确认 B 可作为之后的历史候选。公开自托管入口按 C2d4c3 的验收计划接线。

C2d4c3 先验收已发生副作用但尚未落库的应答。完成 A 的恢复后，在同一实验应用发起第二次获批恢复。一次性 PostgreSQL 的测试触发器只暂停本次部署回执的写入；正常 Komodo 已创建更新并开始运行获批镜像时，终止该批次的专用 Worker。新进程持更高的租约代次接手，只读核对原执行。没有可信原生更新编号时，回执保持待人工核对，保留环境占用，释放全局执行槽。通过独立 Read 身份确认实际运行的容器保持同一实例，并核对写步骤、HTTP/MCP 回执及阻断冲突发布。另行验证已落库更新编号的接管、过期、撤销和目标漂移。通过后接入默认关闭、可显式启用的自托管安装。

C2d4c3b 在同一参考应用先完成 B → A，再批准 A → B。测试触发器只拦截本次处置进入核对的状态写入，此时 Komodo 的实际部署回执已提交。独立回读确认 B 已运行，终止原进程，随后由原批准人撤销发送授权。继任 Worker 使用更高代次读取已记录更新，核验同一实例与入口保护，提交恢复回执并释放环境。最后再次演练没有更新编号的应答中断，核对当前发布仍指向最后一次已核验的实例。已有和缺失编号两条路径分别保存证据。

C2d4c3c 使用独立的托管场景和同样的 A、B 发布步骤，验证发送前的撤销、实际时钟过期和原生目标状态变化。撤销与自然到期后核对任务终态、释放占用及零写步骤，并用独立 Komodo Read 身份确认原 B 仍停在同一实例。最后在 B 停止时批准恢复，派发前由测试维护者重新启动绑定的 B 实例。恢复 Worker 的原生核对必须挡住配置和部署写入，独立回读仍为 B，治理保留待人工核对与环境占用。目标偏移、审批冻结和中英文回执各保存一份可读的实证。

C2d4b 先接通按诊断任务查询的恢复回执。HTTP 与 MCP 共用领域读取，投影当前处置状态、获批版本、已记录的原生更新及独立核验摘要。门户沿用现有交互与中英文文案。随后接入门户确认后的排队，使用服务端提供的安装范围，在持有诊断任务与环境锁时核对原审批人、授权代次、提案指纹、有效期、当前发布实例和恢复目标。真库覆盖读权限、同一批准的并发重试、无有效审批、错误身份、陈旧目标和失效登记。外部 MCP 仅提供读取回执，正式启动入口在 C2d4c 通过后从自托管安装接线。

配置发送前绑定当前实例和固定镜像，部署发送前验证同一执行代次的配置回执。发送授权先提交到数据库，再执行原生请求。接管可读取先前发送和已知回执。无论是否收到响应，已尝试的发送均进入核对路径。

恢复核验读取原生更新 ID、已批准制品和登记入口，并校验恢复容器与此前停止容器不同。收到完成更新并通过受保护健康核对后，回执带入结算。当前版本从已结算的原始发布和恢复事实推导。两个执行器使用同一个全局租约代次，按实际发送的代次消除时钟回拨影响。恢复后，最近一次在同一目标成功发布的不同镜像仍可用于下一次处置。参考安装中的恢复执行闸门归 C2d4 验收。
