# P2-B · 候选冻结与人工确认底座

以合并后的 `main`（`8f1ad45769dce23ef049751e546be11a9638da10`）为基线。目标是验证 P2.4 的候选不可变、确认绑定、过期和撤销语义。依据 [v6 §14](../blueprint-v6.md#14-授权绑定具体交付物与操作) 与 [TS + PostgreSQL 实施计划](../implementation-plan-v2-ts-postgresql.md)。分项交付到独立草稿 PR。

## 候选、确认和范围

- 一个任务按可信证据的单调版本冻结候选，对原 commit、原始及修复快照、差异、模板/规则/检查工具链、复验和最终镜像检查引用、镜像 digest、运行配置、应用环境、目标映射、上线验证和恢复计划绑定 SHA-256 指纹。所有体积较大的材料用摘要引用。演练镜像和检查引用只表示固定样例，不作为正式扫描证据。
- 冻结读取服务端当前证据，并在短事务内对照任务、run、代次和保护环境。相同证据重放取回同一候选、原有效期。不同内容必须提高证据版本；最新冻结候选及当前权威证据同时约束决定。证据端口以后应在同一数据库事务锁定权威记录，变化时提高版本，内容还原也不回退版本。
- 确认命令提供候选指纹、预期决定版本和幂等键。确认、拒绝、撤销均追加独立记录。按任务行串行化冻结和决定，完成行锁后使用 PostgreSQL 当前时间校验有效期与身份。相同请求可返回当前结果，其他决定不能覆盖历史或并发取代。新证据、任务变化、超过证据有效期或失去原授权会使确认失效。
- 个人模式下只允许工作区所有者在其工作区，以服务端配置的人用 OIDC 客户端身份确认、拒绝、撤销。是提交人时记录本人确认。关联当前所有者授权实例，撤销后即使同一主体重新获得所有者授权，旧确认仍然失效。

| 操作 | 可用主体 | 数据范围 |
| --- | --- | --- |
| 读取候选及决定 | 工作区所有者、项目维护者和查看者 | 现有项目读权限，跨项目返回资源不可见 |
| 从当前证据冻结 | 受信任的内部调用方 | 任务本身、当前 run 和同项目环境 |
| 确认、拒绝、撤销 | 已验证的人用客户端身份、当前工作区所有者 | 本工作区当前候选；重验指纹、版本、授权实例和时效 |
| 赋予正式执行资格 | 后续正式交付事务 | 需合格证据、真实目标及执行权；Agent 与外部 MCP 没有批准入口 |

使用现有身份、项目访问判断及中英文文案。当前入口仅有内部领域服务和真实数据库演练，现有授权管理入口继续负责成员。后续页面连接已授权的服务端操作。

## 实施顺序与验收

| 提交 | 内容 | 验收 |
| --- | --- | --- |
| B0 | 本计划 | 把可信样例、正式审批和实际发布的职责分开 |
| B1 | 契约和持久化 | 严格范围和摘要、追加且不可变、迁移适用已有项目和工作区 |
| B2 | 冻结、查看与人工决定 | 只用当前证据；旧版本、失效、跨项目、Agent 或伪造身份不能批准；双语回显 |
| B3 | PostgreSQL 回归与导读 | 同时确认只写一次；事务失败无决定；重启、过期、撤权及内容变化安全；可信样例无发布资格及唤醒 |

验收使用测试 PostgreSQL 17 的领域迁移和最小权限角色。现有 Unit、API、MCP、Worker、门户和可信扫描 CI 继续运行。记录所测范围及正式接入所需证据。
