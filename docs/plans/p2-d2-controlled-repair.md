# P2-D2 · 受控修复与候选制品

本批从正式审计交接到真实修复。修复角色使用当前任务的有证据清单，在一次性虚拟机中生成可重放的补丁和候选快照，将产物交给 P2-D3 独立复验。基线为 P2-D1 已合入的扫描和审计记录。 [P2-D1 PR](https://github.com/MaLaNg116/itervane/pull/22) · [蓝图 v6 第 8 节](../blueprint-v6.md#8-审计修复和复验形成可验证循环) · [实施计划 P2](../implementation-plan-v2-ts-postgresql.md#p2-跑通-agent-审计修复复验和发布)

## 审计交接

- Worker 固定当前任务与运行代次，以及审计清单、已发布检查点、扫描回执、Git 提交、源码清单和策略目录的摘要。恢复时重新查验原记录、当前权限和执行权。
- 修复仅接收可继续处理的正式审计。疑似模式命中保留原确定性。凭据有效性、实际影响和需要所有者确认的条件随交接保存。规则、复验基线和发布标准由平台管理。
- 对同一任务使用独立的修复检查点和受控工具目录。所有动作沿用全局执行槽位、预算、当前项目权限和阶段账本。冲突、持续无进展或缺少可靠证据时进入人工处理。

## 工作区与补丁

- 每项正式修复在合格 KVM Runner 上从已登记来源重新取得当前任务的固定提交，核验原源码清单后，以只读输入和独立候选工作区执行。工作区关闭后确认客体和暂存产物清理。 [现有源码检查](../reviews/p1-d3-worker-inspection.md)
- 优先使用固定版本的模板。模板由平台登记可修改的文件、输入约束和前后断言，Agent 依据受控观察选择。对无合适模板的情形，提供受限文件读取和结构化修改。两种方式共用文件范围、大小上限、前置摘要和提交后的候选校验。
- 改动使用项目内已核验的相对路径、原文件摘要、编辑范围和新内容。Runner 在原字节上重新核对条件，计算修改后的快照。执行位、链接、Git 元数据、平台脚本和受保护基线在独立校验中受保护。依赖修复只使用已核验版本和受管输入，候选锁文件一致性进入复验。
- 候选输出实际可应用的版本化补丁、修改清单及前后快照摘要。给业务方的差异预览以原始变更为依据并对敏感内容实施脱敏。模型只看到明确获准的模拟或公开上下文，按次选择必要片段。疑似凭据相关修改的可导出补丁携带原文件摘要、位置及替换内容，移除的敏感字节由 Runner 在原文件中核对。
- 用动作标识绑定输入、候选、模板版本和执行权。发布确认丢失时先核对已保存的结果与客体清理证据。相同输入和动作重放收敛到既有产物。 [检查点发布与恢复](../decisions/0002-checkpoint-publication.md)

首版结构化补丁使用原文件的 UTF-8 字节区间，当前范围为最多 8 个已有普通文件，每个文件最多 16 处编辑，新增文本合计上限 128 KiB。每个区间的终点为排他边界，Runner 保留未修改的字节和原文件模式，精确校验前置摘要及受保护路径。候选文件树、补丁、清单与回执先在独立暂存目录内校验，再一次发布。原生维护者样例先用已验证的离线客体演练这条路径，正式修复仍以任务授权及专用 Runner 通道为准。

## 合格 Runner 修复请求

- 复用合格控制器的 Unix 对端身份、固定来源、运行工作区锁以及连续授权心跳。控制器显式启用修复请求，并分别校验任务、运行、代次、fence、修复输入、操作 ID、固定源码与命令摘要。当前 Worker 租约通过后才传递有界命令。
- 客体使用单独的修复消息。固定提交读取、取源出口关闭及对象核对通过后，才接收命令并在封存的离线执行身份下应用。命令文件和候选目录随一次性客体回收。控制面保留可重放的规范化补丁与经过核验的制品摘要，私有候选文件树留在客体内。
- Worker 收到经独立清理核对的回执后，再核对本次操作、原输入摘要与修改清单。专用通道先由维护者样例验证。生产 Worker 的执行预留、授权脉冲、回执持久化和重领再通过真实 PostgreSQL 验证。

## 修复操作预留与恢复

- 调用键绑定同一 run 的不可变操作。操作保存选中的审计发现、规范化补丁和工作区，由 PostgreSQL 校验命令原字节摘要。可编辑路径由所选发现推导，npm 依赖修复可包含对应的包清单。执行侧传入受保护的基线路径。
- 每次派发持有单独的请求 ID，记录工作区、镜像、来源和当前 fence。重复调用复用已验回执。租约变更后只在同一工作区及镜像确认空闲时关闭旧尝试，随后以同一操作和新请求重放。工作区无法核对时保留待核对状态。
- Runner 结果必须对应原扫描的 Git 提交对象 SHA-256、树、文件数和快照。当前 Worker 可在授权事务中保存有效回执。撤权、取消或失去租约时，结算只保留已证实的清理状态或待核对记录。

## 修复角色与文件观测

- 修复角色使用独立的正式来源、检查点和恢复预算。输入来自当前已发布审计和固定规则，任务版本与项目权限沿用外层工作流。观察、模型回合、补丁派发和最终入库分别校验当前执行权。
- 文件观测在隔离客体中重核固定提交，按选中的审计发现返回有界路径、字节范围、原文件摘要及模板前提。只在策略明确允许时提供有界的文本片段，命中的疑似凭据行只返回位置和摘要。
- 版本化模板依据确定性的前提生成结构化补丁。非模板路径接收受限编辑建议，使用同一执行服务校验并应用。阶段完成由已保存的回执以及修改说明共同确定。持续无进展、未确认清理或证据不足进入相应的人工或核对状态。
- 修复 ReAct 复用预算、单工具决策和检查点发布。模型按发现编号选择观测，编辑时使用观测编号与目标序号。服务端提取路径和前置摘要。已取得适用模板提示时可以选择模板，结构化修改按观测范围绑定。模型依据实际候选回执结束修复。
- 重领保留已预留的修复动作编号。已预留的补丁应用通过持久化执行服务核对后重放，沿用首次调用预算。模型轮次及缺少清理证据的读取保留人工核对出口。

## 业务队列与候选发布

- 正式修复启用时，完整审计在保存结果的事务内标记本次 run 可进入修复，同一 Worker 持当前租约继续。如果 Worker 在交接后退出，重领根据持久阶段进入修复。已有已确认审计的任务可在预期版本和原项目授权下恢复。零发现审计保留原始快照，供 P2-D3 接入。
- 配置须继续使用现有合格 Runner 和已配置模型，受保护路径由平台配置。入口未启用或配置不可用时保留审计结果和任务边界。修复动作和观测继续经过独立的客体权限、清理及租约闸门。
- 在一个数据库事务中核对当前租约、发布检查点、输入摘要、已记录的操作及其回执，记录不可变修复结果、时间线事件与任务状态。成功状态对应等待独立复验。人工处理、模型中断与清理未获证明分别记录原因。任务停下前等待 Runner 的执行结算。
- 门户、HTTP 和 MCP 读取同一授权结果，展示双语状态、变更路径、文件摘要与变更计数。补丁导出核对当前项目授权、候选摘要及原始命令，提供版本化 UTF-8 编辑内容，原删除字节仍保存在隔离源码中。门户复用现有组件、动效与减少动效偏好。
- PostgreSQL 验收覆盖审计后连续运行、已有任务恢复、重复重领、回执或检查点替换、事务回滚与撤权。浏览器和外部 MCP 验证同一候选、双语显示及授权失败。隔离复验和发布保持各自的后续准入条件。

## 两类缺陷与真实模型验收

- 凭据样例用固定提交中的合成 dotenv 赋值，让模型依据实际语法提示调用版本化模板。用独立计算的行摘要、修改后摘要和保留字节核对结果。
- 依赖样例限定为已登记的 npm 直接依赖，并核对扫描发现、锁文件中的已安装版本与平台所选的可信修复版本。模型只取得明确允许的依赖元数据及必要编辑区间。成功候选由隔离客体验证包清单和锁文件的成对修改，保留非目标依赖与受保护基线。
- 托管 Runner 实测固定来源、两种修复工具、原字节和实际清理。本机通过用户配置的模型协议核对模型在两种观测下的决策，记录调用与结算摘要。分别记录真实推理和真实客体的证据、执行版本与数据范围。
- 缺少版本依据、目标含糊、无进展、清理结果未知时保留明确的待处理状态。独立复验继续验证扫描、构建和平台基线。后续阶段读取已经发布的候选和固定补丁。

## 开发切片与验收

| 顺序 | 交付 | 验收 |
| --- | --- | --- |
| D2.1 | 正式修复输入与产物契约 | 选取最新授权运行的完整审计，固定上游证据及策略。真实 PostgreSQL 证明重复准备幂等，替换快照、外来 run、过期执行权与待人工的审计被拒绝。补丁和候选经过严格契约校验。 |
| D2.2 | 合格 Runner 的工作区和受限修改 | 在新客体重验基础快照。验证模板及结构化编辑、原文件摘要不符、路径或基线越界拒绝、失败回收和可验证结果。受控正常样例检验真实前后字节。 |
| D2.3 | 内置修复 ReAct 角色 | 复用决策、观察和预算机制。至少两种受控观察引出独立选择，覆盖模板修复和受限非模板修改。重复动作、误导性材料、失败调整、取消和撤权均可复跑。 |
| D2.4 | 候选发布与授权读面 | 用当前执行权和精确检查点原子记录补丁、候选摘要及阶段状态。门户、HTTP 和 MCP 读同一结果。中英文标签与现有 GSAP 状态反馈一致，任务文本沿用任务语言。 |
| D2.5 | 原生验证和导读 | 以固定登记的维护者样例跑通审计到修复，比较真实字节差异和快照。两类缺陷分别完成可重放补丁验收，并模拟失败和 Worker 重领。记录实际 KVM 证据与真实模型路径，保存分项提交和代码导读。 |

修复完成进入等待独立复验，P2-D3 负责在干净环境中重放并核对重新扫描、平台基线和针对性测试。P2-E 再固定最终候选、人工确认及 Komodo 实际运行结果。D2 的修复并发仍使用单工作区的全局执行槽位。 [运行验收闸门](../decisions/0001-development-and-runtime-gates.md)
