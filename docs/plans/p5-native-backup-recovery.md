# P5-A2 · 恢复真实交付档案和运维回执

在现有托管 KVM 受保护交付和 Whiskers 重启场景收尾执行同一冷备命令逻辑。使用另一个全新的 PostgreSQL 17 实例和新的文件恢复目录。 [冷备计划](p5-backup-restore.md) · [#160](https://github.com/MaLaNg116/itervane/pull/160)

1. 保留已验证发布、已恢复重启、因回执中断待人工核对的重启，以及两次后续任务使用的已发布 Runbook。关闭源 API 和消费者连接，使用清单指定的保留档案及三个原生安装文件制作冷备。
2. 恢复到隔离实例，核对同一发布候选、验证及编排历史的摘要、重启环境占用、Runbook 的已审版本和任务引用。用独立 OCI 元数据读取器检查恢复后的文件确实包含已发布 manifest。
3. 对账前保持恢复端所有消费者关闭。独立核验既有入口对匿名请求持续返回 401 或 403。托管报告只保存必要的计数、身份无关摘要和判据，备份包与重建的库均留在临时环境。
