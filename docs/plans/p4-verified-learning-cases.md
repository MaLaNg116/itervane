# P4-B1 · 从正式任务记录提炼案例

接续 [#136](https://github.com/MaLaNg116/itervane/pull/136)。案例作为规则提炼 Agent 的证据来源，保留真实任务、运行、结算摘要和经核对的结果。项目当前授权决定可见范围。 [P4 总计划](p4-rule-learning.md)

1. 项目写入角色从已完成独立复验的修复任务选取代码案例。案例只收录已解决且没有新增的扫描发现，或从原异常到修复通过的受信健康续测。校验固定快照、修复及独立复验的来源。
2. 运维案例从已正式结算的诊断任务选取。第一种处置为受控重启，校对诊断、门户批准、原生回执、独立恢复证明、同实例、启动时间变化和受保护健康结果。未确认处置不生成成功案例。
3. 以原项目、运行和案例类型去重，把摘要、采集人及授权代次写入不可变记录。同类过滤使用结构化症状分类。案例内容不复制日志、凭证、模型自由文本、源码或补丁。
4. HTTP 提供按项目与类型读取，以及从确切任务运行建立案例。双语字段在读取时投影，版本绑定保持稳定。真库覆盖并发、错误版本、项目撤权、恢复未结算、不可变约束及来源隔离。

后续批次用确定性模型用例验证 Agent 的查重、候选生成、异常停止和租约恢复，并用托管实际任务验证案例和候选。正式规则使用单独的隔离样例、人工审核和发布闸门。
