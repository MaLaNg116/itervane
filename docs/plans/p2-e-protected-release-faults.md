# P2-E-D3-D3-C · 真实上线核验与恢复负例

接续 [批准后变更验收](p2-e-protected-release-drift.md)。在专用托管 KVM 上使用真实 Registry、Komodo、Traefik 和 Keycloak。构建和独立复验通过后，由外部 MCP 冻结候选，门户身份确认。

1. 在实际 Komodo 更新标识已入库时中断 Worker。让新执行者回读同一标识，校验已确认的步骤、代次和原生更新数量。写入结果未知的原生路径沿用已有验收，核对仍占用环境且不产生第二次派发。
2. 已部署的合成服务先返回健康 200。测试向本轮容器发送固定信号，让服务在保持版本和镜像的情况下返回 503。安装态 Worker 复核实际入口，任务进入人工核验，归档同一沙箱镜像和原生更新。
3. 第二个独立部署保持应用健康，停止本轮 Keycloak。记录实际匿名请求仍被拒绝，正式探测无法取得凭证，任务进入人工核验。两个结果都要用中英文 HTTP、MCP、PostgreSQL 和原生读回核对。

两个负例使用单独任务与运行目标，保留各自的批准、外部写入和核验记录。真实发布 Worker 使用正常安装入口。报告保存重领后读回、阻断状态和清理，保留未知写入的人工处理边界。
