# P3-C3-C3b · 由故障复现进入关联修复与复验

接续 [#127](https://github.com/MaLaNg116/itervane/pull/127) 的原版隔离复现。沿用 [阶段计划](p3-c-linked-repair-reproduction.md) 和 [运行闸门](../decisions/0001-development-and-runtime-gates.md)。给已人工确认的关联任务补齐从故障证据到可审批的新发布候选。

1. **冻结交接并事务入队。** 原版复验须完成可核验的审查，完成标准构建与五项基线，续测得到同版本应用 503，源码扫描完整且无未处置发现。重读健康事件、原发布、当前确认人的授权和已登记的标准配置。复用任务代次、执行租约与 pg-boss，一次事务登记有上限的关联修复代次。新的交接类型绑定原始快照和复现回执，既有常规返修账本保留历史摘要。
2. **受限编辑。** 正式审计和修复读取这项结构化应用故障证据。修复 Agent 使用现有隔离源码观测与补丁工具处理标准应用的 `server/app.mjs`，文件边界由受管配置确定。仅允许公开或合成的固定源码，完整扫描后从独立 VM 返回有大小上限的 UTF-8 内容、字节边界及摘要。配置、平台基线和锁文件受现有保护。已授权的 Worker 校验提出、应用和读取回执的范围，修复仍保留可导出差异。
3. **独立复验与候选。** 在新 VM 重放实际补丁并扫描，要求五项基线、同条件健康续测和独立镜像核验通过。正式候选绑定原始复现、修复后的快照、目标登记与完整配置。提交审批、领用发布和受控写入重新核对当前授权、目标和版本。原版续测通过、结果未知、缺少能力、再次 503 或授权失效均有双语状态及人工处理入口。

真实 PostgreSQL 验收覆盖只入队一轮、事务回滚、撤权与重授、配置或实例变化、租约接管和历史返修。修复与复验增加源码观察边界、作用域外修改、响应不明、同版故障持续及健康通过回归。用托管 KVM 核对固定应用的源码观测、可导出补丁、独立 VM 的同条件回执及清理。受保护发布后的真实故障到新实例恢复由 C3-C3c 验收。
