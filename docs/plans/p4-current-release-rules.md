# P4-D4a · 规则变化使旧发布授权失效

发布关联固定源码、复验结果、制品和目标。本批把任务规则快照纳入候选证据，并在写入前重新核对适用范围和已发布版本。 [P4 计划](p4-rule-learning.md) · [#156](https://github.com/MaLaNg116/itervane/pull/156)

1. 冻结候选时核对任务固定规则和当前适用规则，记录快照摘要。首次适用规则的发布也可影响先前的空集合任务。历史空集合与旧候选保留读回和兼容入口，按实际当前规则判断是否仍具有效果权限。
2. 在门户确认、队列领取及注册表和 Komodo 发送前复核规则，规则变更后旧候选进入证据变化状态。使用任务接收与激活共用的数据库锁，约束持久化的候选、确认与新发送意图。已发送或结果不确定时沿原绑定做只读对账。
3. 用 PostgreSQL 验证历史候选、新规则发布或撤回、排队工人拒绝旧授权和已结算检查读回。后续批次负责跨任务失效与运维等待审批的即时对账。
