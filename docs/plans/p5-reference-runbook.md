# P5-B6 · 在参考环境发布并复用真实恢复案例的 Runbook

使用参考发布与运维批次保留的真实恢复。让同一安装的维护者保存该案例，经规则提炼、正反样例验证和真实门户审核发布。下一次停机仍从真实健康事件派发，核对正式诊断和处置提案消费同一个已发布版本，再完成独立审批与健康恢复。 [参考运维 #166](https://github.com/MaLaNg116/itervane/pull/166) · [原生 Runbook 复用](../reviews/p4-native-runbook-reuse.md)

1. 基于已核对的恢复摘要保存案例。通过启用正式模型指纹的 API 提交提炼，用现有 Worker 执行实际 ReAct 工具。样例验证必须覆盖当前停止实例、健康实例、过期发布与审批缺项。
2. 维护者使用真实门户身份准备与样例绑定的规则草稿，完成审核和发布。记录候选、验证、审核、版本、激活编号和适用范围。
3. 对当前受保护实例进行新的停机观察。复用相同健康调度和双审批恢复，核对诊断规则快照、提案约束，以及数据库、门户和外部 MCP 对同一版本的读回。
4. 代码规则单独使用真实的应用健康修复作为提炼案例，匹配候选检查的适用范围。该批继续完成同一参考安装下的正反样例和后续任务复用，两类证据一起用于最终 P5 验收。
