# P2-D3-C2-C · 同一候选的客体运行与 HTTP 基线

在 [离线构建 #28](https://github.com/MaLaNg116/itervane/pull/28) 的固定快照、构建 profile、dist 摘要和 VM 执行权基础上，验证实际启动的标准应用。使用 [独立 HTTP 基线](../reviews/p2-d3-c2-standard-baseline.md) 及现有隔离资格。C3 将可验证的同一运行目录交给镜像产物步骤。

## 受保护运行

1. 复验输入显式申请运行基线，绑定已有构建 profile 和基线摘要。执行前复核 Runner 资格和当前租约。构建失败或缺证时不启动应用。
2. 构建进程退出后，由封存的准备程序重新读取有界的 dist 及摘要，从不可变输入取回服务端源码和锁文件。准备程序使用独立目录及离线 npm，按锁定输入安装生产依赖并关闭 lifecycle 脚本。
3. 应用和测试各用独立非 root 账号。应用只读挂载经核验的运行目录，使用没有外部网卡的客体私有回环。测试账户沿用封存程序发起有界请求，拒绝重定向。校验同一任务的起始输入、dist 和基线程序，应用账号不能写检查证据。
4. 检查完成或失败后停止应用控制组。通过独立退出回执与最终 VM 清理核对进程已经回收。回执包含受保护检查结果、运行目录身份及正常结束或失败的原因。

## 开发与验收

| 批次 | 交付 | 验收 |
| --- | --- | --- |
| C1 | 运行目录和产物托管 | 复验校验测得的 dist 与独立源投影，拒绝替换和越界文件。生产依赖来自同一已校验离线缓存。 |
| C2 | 受限应用与独立基线 | 标准正例在 KVM 完成实际离线构建、真实 HTTP 五项检查和退出。固定回归场景在同一链路返回 503 并保留失败证据。 |
| C3 | 回执及取消回归 | 构建身份不能提交或改写基线回执。旧租约、替换检查材料、不完整证据与清理未知均不能形成合格结果。至少一次实机核对停止时应用已启动。 |

初次目标沿用无状态 Linux amd64 标准应用，只使用合成数据。P2-D3-D 接入生产 Worker 和复验 Agent，P2-E 依照既有审批闸门执行发布。 [P2-D3 计划](p2-d3-formal-verification.md)
