# P4-D2a · 已发布代码规则扫描固定源码

接续 [#146](https://github.com/MaLaNg116/itervane/pull/146)。本批次将任务快照中的代码规则编译为固定 Semgrep CE 配置，并从来宾里的已核验源码得到可独立复核的报告。 [规则快照计划](p4-task-rule-snapshots.md) · [规则样例 Runner](p4-native-rule-samples.md)

1. 输入固定项目、源码版本、源码清单、任务规则集合、通过样例验证的规则与 Semgrep 输入摘要。代码规则按包标识编译和归一化，保留版本与审核引用。声明语言以 MVP 的 JavaScript 和 TypeScript 为限，覆盖源码清单中匹配的扩展名。
2. 来宾独立清点已验证源码，用固定命令执行本地规则配置。每个临时目标与原路径和内容摘要成对绑定。验证实际扫描覆盖、引擎与规则摘要，结果只保存范围、坐标和摘要。无适用文件、发现命中和执行不可用有明确证据状态。
3. 运行单元和真实固定 Semgrep 的可信源码 Smoke。使用和来源案例及生成样例不同的处理器与文件名，检查匹配、正常反例、工具摘要、遗漏文件与结果篡改。

P4-D2b 把同一执行器接入 Runner 的租约、一次性域、固定源码通道和正式审计与复验。P4-D2c 使用第二个登记项目和独立提交完成托管联验，后续授权失效和 Runbook 处置保留各自的运行闸门。
